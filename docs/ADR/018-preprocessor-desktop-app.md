# 018. 전처리기 창 프로그램 — PySide6 + 폴더형 실행파일, 여러 회차 동시 처리, 창 안 검수

- 상태: 확정 (2026-10-20, 세션 #9) — 전처리기 v0.3.0
- 관련: ADR 012(명령줄 MVP·HTML 검수), 개발기준서 D8(PySide6 + PyInstaller)
- 사용자 결정(세션 #9): ① **PC 전용**(폰·태블릿 아님) ② 방식 **A(창 프로그램)** ③ **동료에게 나눠 준다** — 원큐합격 앱과 함께 사내 경진대회 출품(직원 추천 최다 상금)

## 배경

- 명령줄은 파이썬 설치·`pip install`·PowerShell 따옴표·폴더 위치(`..\source_pdf`)에서 막힌다(세션 #9 실제로 세 번 막힘). 동료에게 나누려면 설치 없이 더블클릭.
- 검수: HTML 보고서 → [검수 파일 저장] → 내려받은 파일을 `review/`로 옮김 → 같은 명령 다시 실행. 단계가 많다.
- 처리 시간: 회차당 약 10초(클라우드 1코어). 20~30회차 → 3~5분. 코어를 나눠 쓰면 줄일 수 있다.

## 결정

1. **구조**: 처리 규칙은 화면과 분리한 `oneq_prep/batch.py`(일괄 처리)·`review.py`(검수 파일 규칙)에 두고, 명령줄(`pack.main`)과 창(`oneq_prep/gui`)이 함께 쓴다. 화면 도구를 바꿔도 처리 코드는 그대로.
2. **여러 회차 동시 처리**: `ProcessPoolExecutor`(spawn — Windows와 같은 방식), 기본 `코어 수 − 1`(최대 4, 회차 하나가 288dpi로 그려 메모리를 씀). 회차마다 따로 — 한 회차 오류가 나머지를 멈추지 않음. [멈추기]는 지금 회차까지. 구기준 회차(재배정)는 현행 회차가 끝난 뒤.
   - 결과 팩은 순서 처리와 바이트 단위로 같다(시험 `test_parallel_equals_sequential`). 클라우드 2코어: 6회차 40초(회차당 약 6.6초).
3. **창 화면**(`python -m oneq_prep.gui` / `OneQ-Prep.exe`)
   - ① 종목·팩 저장 폴더(기본: 문서\원큐합격 문제팩)·만든 사람·원본 출처·문제 종류·동시 처리 수 — 다음 실행 때 기억
   - ② PDF 목록: 끌어다 놓기·[PDF 추가]·[폴더 추가](하위 폴더 포함). 파일 이름으로 시행일·팩 이름을 **처리 전에** 보여 줌, 시행일이 없는 파일은 표에서 직접 입력, 같은 팩 이름 중복 경고
   - ③ [팩 만들기] → 진행 막대, "n / 전체 회차 끝 · 동시에 k개 처리 중 · 경과 · 남은 시간", 회차별 상태(대기·처리 중·팩 생성·검수 필요·오류)
   - **검수 창**: 회차를 두 번 누르면 문항 카드(이미지·정답·과목·제외·경고·재배정 제안). 기본은 확인할 문항만, [전체 문항]. [저장하고 이 회차 다시 만들기] = 검수 파일 저장 + 그 회차만 다시 처리(회차 번호는 목록 전체 기준이라 그대로). 출제기준에 없는 과목명은 창 위에서 표준 과목/제외로 연결
   - HTML 보고서는 그대로 만든다([검수 보고서(웹) 열기]) — 여러 회차를 훑어보기 용
4. **배포: PyInstaller 폴더형(onedir)** + zip(`dist\OneQ-Prep-<버전>-win64.zip`). `packaging/build_exe.ps1`이 가상환경 → 시험 → 빌드 → 실행파일로 PDF 2개 처리 점검(`--cli`) → zip → Defender 검사까지.
   - 폴더형: 실행할 때마다 임시 폴더에 풀지 않아 빨리 뜨고, 단일 파일보다 백신 오탐이 적다고 알려짐. UPX 압축 안 씀. 실행파일 속성(회사·제품명·버전)을 채움.
   - **Qt LGPL v3**: exe에 Qt를 함께 넣어 직원에게 나누는 것은 사내라도 Qt를 '배포'하는 것으로 본다. 폴더형이라 Qt DLL이 별도 파일로 남아 교체 가능 + `THIRD-PARTY-NOTICES.txt`(도움말 메뉴에서도 열림)에 라이선스·소스 위치. 법률 판단은 아님 — 출품 전 사내 확인 권장.
   - `PySide6-Essentials`(웹엔진 등 빼고 기본 모듈만)로 크기를 줄임. 리눅스 시험 빌드 267MB(전체 PySide6) — Windows Essentials는 더 작을 것으로 예상, 실측은 사용자 PC.
   - 실행파일에서도 `OneQ-Prep.exe --cli …`로 명령줄 처리(점검·일괄 작업). 콘솔이 없으므로 기록은 `oneq-prep-cli.log`.

## 검토한 대안

- **Nuitka / `pyside6-deploy`**(Qt 공식 도구, 내부적으로 Nuitka): 백신 오탐이 적다는 주장이 있으나(도구 판매 업체 블로그) 빌드 5~15분·C 컴파일러 필요. 회사 백신에서 PyInstaller exe가 막히면 다음 후보 — `build_exe.ps1` 5단계 Defender 결과로 판단.
- **단일 파일(onefile)**: 나눠 주기는 쉽지만 실행마다 압축 풀기(수 초), 오탐 증가, LGPL 교체 가능성 불리.
- **QtWebEngine으로 HTML 검수 화면 재사용**: 크기 +100MB 이상, 회사 PC GPU·보안 설정에 민감 → 검수 카드는 Qt 위젯으로 새로 그림.
- **코드 서명 인증서**: 오탐을 줄이는 가장 확실한 방법이지만 비용 — 출품 단계에서 회사가 지원하면 검토(BACKLOG).
