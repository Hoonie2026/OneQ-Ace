# 012. 2단계 전처리기 MVP — 명령줄 + HTML 검수 보고서, 출제기준 프로필, 형광펜형·스캔본

- 상태: 확정 (2026-10-18, 세션 #7)
- 관련: ADR 001(oqp/1), ADR 005(출제기준은 전처리에서), 개발기준서 D8~D11, 8장 2단계
- 사용자 결정(세션 #7): ① 2011년 구기준 3회차는 우선 빼고 2012~2022 31회차로 실기기 확인 ② MVP 형태는 **명령줄 + HTML 검수 보고서**(PySide6 창 프로그램은 뒤로) ③ 지원 형식: comcbt 교사용 + 형광펜 표시형 + 스캔본(OCR) + 종목 프로필

## 결정

1. **실행 한 줄**: `python -m oneq_prep <PDF…> <출력폴더> --cert 종목 --prepared-by 이름`
   - 막히는 문제가 없는 회차만 팩(zip)을 쓴다. 문제가 있는 회차는 `review/<packId>.review.json`(검수 파일)을 남긴다.
   - 언제나 `review/report.html`(요약)과 `review/<packId>.html`(문항 카드)을 만든다. 서버·설치 없이 브라우저로 연다.
2. **검수 화면 = 정적 HTML**: 카드마다 문항 이미지·정답·출처·과목·경고·재배정 제안. 정답·과목·제외를 고치고
   **검수 파일 저장** → 내려받은 파일을 `review/`에 넣고 같은 명령을 다시 실행하면 반영된다(멱등).
   - 검수자 정답은 보기 표시·정답표보다 우선(`answerCheck: corrected`). `reviewed: true`이면 `manifest.reviewedAt` 기록.
3. **출제기준 프로필** `preprocessor/standards/<종목>.json`(ADR 005 구현): 현행 과목(이름·순서·문항 수), 별칭, 제외 과목, 구기준 회차(`legacy.before`).
   - 과목명 비교는 공백·가운뎃점·괄호를 무시(`수리학및수문학` = `수리학 및 수문학`).
   - 팩의 과목명·번호는 프로필 기준. 프로필에 없는 과목명은 막힘 → 검수 파일 `subjectMap`.
   - `draft: true` 프로필은 팩을 만들지 않는다(RAILCIVIL은 현행 과목 확인 전 초안).
4. **팩 포맷 보완(oqp/1 유지, 선택 필드 추가)**
   - `manifest.excluded[]`: `{subject, nos, reason(abolished-subject|unreadable|other), note?}` — 여기 적힌 번호만큼 문항번호가 비어도 된다(NUMBERING 규칙 완화, 두 검증기·공용 사례 5건 추가).
   - `manifest.standard`: `{profile, version, renamed?, reassigned?}` — **과목을 손댄 팩에만** 쓴다. 손대지 않은 팩은 이전과 같은 모양이라 앱 v0.6.0에서도 열린다.
   - 문항 flags에 `subject-reassigned`, `ocr` 추가.
   - ⚠ `excluded`·`standard`가 든 팩(재배정한 2011 팩, 폐지 과목이 있는 종목)은 **앱 v0.6.1 이상**이 필요 → 배포 후 게시.
5. **형광펜 표시형**(한솔 경향문제 등): 노란 채움 사각형이 겹친 보기 번호 = 정답. 렌더링 전에 PDF 객체 단계에서 그 사각형만 지운다(보기 번호 크기 이하만 — 그림 속 노란 면 보호). 잔존 검사에 노란 픽셀 비율 추가.
   - 과목마다 번호가 1부터 다시 시작하는 형식: 번호가 1로 돌아가면 새 과목, 과목명은 페이지 위쪽 "(과목명)" 제목줄. 팩의 `no`는 시험지 전체 순번(1~120), 카드에 "원본 ○과목 ○번" 표시.
   - cropbox가 mediabox와 다른 PDF: 렌더링 시 cropbox를 mediabox로 맞춰 pdfplumber 좌표와 일치시킴.
   - 여러 페이지 단 첫·끝 줄에 되풀이되는 안내문("※ 본 콘텐츠는…")은 문항에서 빼고 크롭 경계로 쓴다.
6. **스캔본(OCR)**: 텍스트층이 거의 없으면 Tesseract(kor, 선택 설치)로 글자 좌표를 만들어 같은 추출기에 넣는다.
   - OCR은 원문자·문항번호를 자주 잘못 읽는다 → 문항 시작은 "단 왼쪽 끝 + 번호 모양 머리"로, 번호는 순서로 매긴다. 보기 번호는 짧은 기호 토큰 위치로 찾고 문항 안 순서로 1~4.
   - 정답: 진하게 칠한 보기 번호(잉크 비율) → 그 자리를 지우고 글꼴로 일반 원문자를 다시 그림. 못 찾으면 검수 파일 수동 입력.
   - 과목별 문항 수를 프로필과 대조해 경계 누락을 막힘으로 보고. OCR 팩 문항은 모두 `ocr`·`needs-review`.
7. **구기준 회차 재배정**(ADR 005 추가 절): 현행 회차 문항과의 글자 2-gram 코사인 유사도 k=7 투표로 과목을 제안하고, 검수 파일 `reassign`에 미리 채운다. `reviewed: true`가 되기 전에는 팩을 만들지 않는다. 참조 문항은 같은 실행의 현행 회차, 없으면 출력 폴더의 기존 팩.

## 실측 (세션 #7, 클라우드 작업 환경)

- 측량 34회차 재처리: 2012~2022 31회차 팩이 **1단계 팩과 문항·이미지가 바이트 단위로 같음**(manifest의 generator·createdAt만 다름). 2011 3회차는 재배정 검수 대기.
- 2011 재배정 제안: 회차당 31~33문항 — 61~80번 18~20문항 → 측량학, 41~60번 8~10문항 → 지리정보시스템(ADR 005 대조 결과와 같은 양상). 나머지 1~3문항은 경계 주제라 사람 판단.
- 토목기사 2024-3 경향문제: 120문항·6과목, 형광 표시 120개 모두 정답으로 읽고 지움, 검증 통과(3.6MB).
- 스캔본: 실제 스캔 PDF가 없어 교사용 PDF를 200dpi 이미지로만 만든 PDF로 시험. 과목 5개는 모두 찾았지만 문항 경계 95/100, 보기 4개를 다 찾은 문항 약 2/3 → **실제 스캔본(PDF ③)으로 다시 맞춰야 함**. 지금은 보고서로 막고 사람이 확인하는 수준.

## 검토했으나 보류

- PySide6 창 프로그램·PyInstaller exe: 기준서 D8대로 가되, 검수 흐름을 HTML로 먼저 굳힌 뒤(7단계 전) 감싸기
- OCR 문항 경계에 "보기 줄 뒤 넓은 간격이면 새 문항" 규칙: 놓친 문항은 줄었지만 잘못 나눈 문항이 생겨 되돌림
- 재배정에 scikit-learn TF-IDF: 의존성 추가 없이 numpy로 충분. 6단계 유사 문항 군집 때 함께 교체 검토
