# ADR 032 — 보충 문서: 스캔본에서 만들지 못한 문항을 직접 타이핑해 더하기

- 상태: 채택(생성기 0.5.0-dev.46, 2026-11-18 세션 #22)
- 계기(사용자): 철도토목기사 15회차에서 머리 찾기 규칙을 다듬은 뒤에도 33문항(판독 불가 15 · 다음 문항과 붙어 자동 제외 13 ·
  끝 문항이 기록 없이 사라짐 5)이 남음 → 규칙을 더 늘리는 대신 사용자가 회차마다 직접 타이핑한 PDF로 채우기로.

## 결정

1. **알아보기**: 첫 쪽 위쪽 다섯 줄 안에 "2014년 철도토목기사 2회 보충"처럼 연도·회차와 '보충'이 있으면 보충 문서(`supplement.header`).
   연도·회차는 이 줄에서 읽는다(파일 이름은 쓰지 않음 — ADR 021 2절). 회차를 적지 않으면("2014년 철도토목기사 필기 보충")
   그해 원본 회차가 같은 묶음에 하나뿐일 때 그 회차로, 둘 이상이면 회차를 적어 달라는 오류(dev.47).
2. **읽기**: 1단 글자 PDF. 문항 번호는 시험지 번호 그대로(이어지지 않아도 — `analyze(free_numbers=True)`), 단 나눔 없이 1단,
   문항 그림 폭은 글상자 폭(왼쪽 여백과 같은 오른쪽 여백). 정답은 채운 원문자(❶~❹)로, 없으면 정답 미지정(ADR 028).
3. **합치기**(`supplement.merge`, 일괄 처리 마지막): 같은 묶음에서 처리한 원본 회차 문제팩의 **빠진 번호 자리에만** —
   판독 불가, 다음 문항이 붙어 망가진 문항, 기록 없이 빠진 번호. 원본에 멀쩡히 있는 번호·폐지 과목 번호에는 넣지 않는다.
   과목은 과목마다 문항 수가 같으면 그 크기의 번호 구간(예: 20문항)으로, 아니면 바로 앞 번호 문항의 과목.
   원본 회차가 같은 묶음에 없으면 오류("원본 회차 PDF를 함께 올려 주세요") — 원본 문제팩을 덮어쓰지 않게.
   보충 문서는 따로 팩을 만들지 않는다. 학습 기록은 문항 번호(qid)로 이어진다.
4. **작성 규칙**(사용자 안내 — 앱은 문항을 그림으로 보여 주므로 글자 크기는 작성 단계에서 맞춘다):
   A4, 1단, 좌우 여백 6cm(글상자 폭 9cm ≈ 원본 시험지 한 단), 맑은 고딕 11pt, 줄 간격 1.15, 문단 간격 0(문항 사이만 10pt).
   클라우드에서 LibreOffice로 같은 설정 PDF를 만들어 원본 스캔 문항과 나란히 비교 — 글자 크기가 원본과 비슷하거나 조금 큼.

## 검토한 대안

- 머리 찾기 규칙을 더 늘리기 — 남은 문항은 번호·경계 단서가 없어 다른 회차를 망가뜨릴 위험이 큼(세션 #22 GPT 검토와 같은 결론).
- 엑셀 등 표로 입력받아 글자를 그림으로 그리기 — 그림·수식을 넣기 어렵고 원본과 모양이 달라짐.
- 학습앱이 글자를 직접 그리기(기기 글꼴 크기 반영) — 기출 그림·수식·표를 그대로 보여 주는 지금 방식(문항 그림)과 맞지 않아 BACKLOG(글자 크기 설정).
