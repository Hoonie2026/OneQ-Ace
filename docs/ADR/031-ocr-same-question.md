# ADR 031 — 스캔(OCR) 문제팩의 같은 문항 묶기

- 상태: 채택(앱 0.21.0, 2026-11-18 세션 #22)
- 계기: 세션 #21 최종 점검 — 학습 원리 화면은 "같은 문항은 하나로 묶어 한 번 익히면 모든 회차에 반영"이라고 하지만,
  같은 문항 판정(`sameKey`)이 글자 완전 일치라 스캔 문제팩에서는 한 번도 묶이지 않았다(철도토목기사 15회차 0묶음).
  그래서 "n회 출제", 자주 나온 문항 먼저, 한 번 익히면 모든 회차 반영, 지정한 정답 전파가 스캔 문제팩에서 안 됐다.

## 측정

철도토목기사 15회차(2008~2022) — PC Windows OCR 기록으로 클라우드에서 문제팩을 다시 만들어(1,149문항) 같은 과목·다른 해의
문항 쌍을 한글만 남긴 글의 2-gram tf-idf 코사인으로 대조하고, 구간마다 표본을 직접 읽어 판정했다.

| 전체 글 유사도 | 판정 |
|---|---|
| 0.85 이상 | 같은 문항(OCR 잡음만 다름) |
| 0.65~0.85 | 대부분 같은 문항. 드물게 보기를 바꾼 변형, 숫자만 바꾼 계산 문항, 물음 방향이 반대인 문항 |
| 0.55~0.65 | 같은 문항과 변형이 섞임(승강장 높이 밑면 ↔ 윗면, 반력 RA ↔ RB 등 정답이 다른 변형) |
| 0.45~0.55 | 같은 개념의 변형이 많음 |

## 결정

1. **학습 단위 묶기**(`engine/ocrSame.ts`): OCR 문항이 낀 학습 단위끼리만, 같은 과목·다른 회차에서
   유사도 ≥ 0.65 이고 안전장치를 모두 통과하면 하나로 묶는다. 유사도 높은 쌍부터 묶고, 묶음 안에 같은 회차 문항이 둘이 되면 묶지 않는다.
   - 물음 방향: 한쪽 "옳은·알맞은", 다른 쪽 "옳지 않은·틀린·아닌"이면 안 묶음(OCR이 낱말을 놓쳐 방향을 모르면 막지 않음)
   - 숫자: 둘 다 숫자 6자 이상이면 숫자만 남긴 글의 2-gram 코사인 ≥ 0.6 (곡선반경 400m ↔ 300m 슬랙 같은 계산 변형)
   - 보기 글: 물음표 뒤 한글 2-gram이 둘 다 12종 이상이면 코사인 ≥ 0.5 (보기를 통째로 바꾼 변형)
   - 한글 2-gram 12종 미만(그림·수식뿐, OCR 실패)은 묶지 않음
   결과: 1,149문항 → 1,032 학습 단위(103묶음·220문항, 최대 5회 출제). 무작위 22쌍 확인에서 21쌍이 같은 문항, 1쌍(보기를 바꾼 변형)은 보기 글 기준으로 걸러짐.
   **안전장치에 걸린 쌍은 버리지 않고 변형으로 분류한다**(사용자 2026-11-18: 같은 주제인데 옳은 것/틀린 것을 묻는 문항, 숫자만 바꾼 계산 문항은 변형):
   `ocrMerge`가 이 쌍을 `bank.variantLinks`로 돌려주고, 변형 군집(`buildConcepts`)은 유사도와 관계없이 이 쌍을 같은 군집에 넣는다.
   출제 구성 실측(`examShares`)도 같은 규칙 — 가장 비슷한 앞 회차 문항과 유사도 ≥ 0.55여도 안전장치에 걸리면 "같은"이 아니라 "변형"(모든 문제팩).
   철도토목: 변형으로 분류된 쌍 26(숫자 21·물음 방향 3·보기 1·기타 1), 모두 같은 변형 군집. 출제 구성 같은 44% → 37%, 변형 14% → 21%.
   숫자 비교 전에 보기 원문자(①②…)를 뺀다 — NFKC가 숫자 1·2…로 바꿔 숫자가 같은 문항도 다르게 보이던 것.
   글자층 문제팩(comcbt 등)은 예전 그대로(글자 완전 일치) — 숫자만 바꾼 변형을 잘못 묶을 위험이 없게.
2. **정답 지정 전파**: 같은 학습 단위의 다른 회차 문항에는 **글이 보기 순서까지 같을 때만** 정답 번호를 옮긴다(`orderKey`).
   기출은 해마다 보기 순서가 자주 바뀌어(예: 분기기 입사각 2008 ↔ 2016) 순서가 다르면 같은 번호가 다른 보기다.
   OCR 글에서 보기를 안정적으로 나눌 수 없어(1,149문항 중 114개만 네 보기로 나뉨) 보기 글로 위치를 맞추는 방식은 쓰지 않았다.
   대신 정답 미지정·확인 필요 문항에서 같은 단위의 다른 회차 문항에 정답이 있으면 "참고: 같은 문항으로 묶인 ○○년 ○회 문항의 정답은 ③ —
   보기 순서가 다를 수 있으니 비교해 정해 주세요" + [그 문항 보기](그 회차 문항 그림)를 보여 준다. 정답을 정하는 것은 학습자.
   전파한 문항의 정답도 그 문항 contentHash로 저장해 문제팩을 다시 가져와도 남는다.
3. **변형 군집**(`similarPairs`): OCR 단위끼리는 같은 한글 정규화로 비교하고 기준 0.5(출제 구성의 변형 기준 쪽). 글자층 단위와는 비교하지 않음.
   철도토목 15회차: 33군집 → 82군집(최대 8 — 트러스 부재력 계산 문항들). 글자층 문제팩은 그대로라 엔진 게이트(측량 가상 문제은행) 19/19 변화 없음.
4. **생성기 정답 교차 확인**(`crosscheck.py`)은 바꾸지 않음 — 보기 글로 정답 위치를 맞춰야 하는데 OCR 글은 보기를 나눌 수 없다.
   유사도로 다른 회차 정답을 문제팩에 넣으면 틀린 정답이 "교차 확인"으로 들어갈 수 있어, 정답 미지정으로 두고 학습앱의 참고 표시로 갈음.
5. 계산 방식이 바뀌어 `SHARES_VERSION` 4 — 기기에 저장된 군집을 다시 계산한다. 학습 기록은 문항 번호(qid)로 저장돼 있어 묶음이 바뀌어도 다시 계산된다.

## 남은 일

- 실제 사용에서 잘못 묶인 문항이 보이면 기준(0.65·안전장치)을 다시 본다 — 사용자 판정 표본이 쌓이면.
