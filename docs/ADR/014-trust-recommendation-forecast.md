# 014. 추천·예상 점수의 신뢰 — 실제 앱 알고리즘 검증, 합격 가능성·실제 학습량 경고, 근거 화면

- 상태: 확정 (2026-10-19, 세션 #8) — 앱 v0.8.0
- 관련: ADR 006·007(엔진·게이트), 008·013(실제 시험 기준 예상), 010·011(추천 학습), docs/engine-gate.md
- 계기: 사용자 요청(전처리기로 넘어가기 전 마지막 점검) — "꾸준히 하면 합격한다는 믿음", 계획·남은 기간·학습 패턴상 개선 없이는 합격이 어려우면 경고, 예상·추천은 과학적 근거와 설득력, 추천 문항 수의 동적 산출과 그 과정 공개, 홈에 학습 원리 설명 단추

## 1. 점검에서 찾은 문제

| # | 문제 | 영향 |
|---|---|---|
| ① | **화면이 쓰는 추천(시스템 추천 = `buildDailySession`)은 게이트가 검증한 알고리즘(주간 계획 엔진 `planWeek` + `buildTodaySession`)이 아니었다** | "가상 학습자로 검증했다"는 말이 실제 앱에는 해당되지 않음. `session.ts` 머리말의 "교차 학습"도 화면 경로에는 없었음 |
| ② | 홈의 상태(배지)는 실제 시험 기준(exam mix), 합격 기준 경고의 필요 시간은 보유 기출 기준(bank) | 기준이 섞임 |
| ③ | 예상은 "계획대로 한다면"뿐 — 실제 학습량(계획 이행)을 보지 않음 | 계획만 크게 세우고 안 하면 예상이 계속 낙관적 |
| ④ | 예상 점수만 있고 합격 가능성이 없음, 계산 과정·근거가 화면에 없음 | 믿고 따를 근거가 안 보임 |

## 2. 실제 앱 알고리즘을 게이트에 넣고 비교 (`sim.ts` policy `daily`, `exp.test.ts`)

가상 학습자 3종 × 60·30·14일 × 시드 3, 같은 날짜별 학습시간. 합격 확률 = 과목당 20문항 이항분포(시나리오 평균).

| 비교(위기 대응형 평균, 같은 시간) | 합격 확률 |
|---|---|
| 화면 추천 v0.7 그대로 | 80.9% |
| 주간 계획 엔진 세션(4단계 게이트 방식) | 69.2% |
| 회차 순서대로 + 틀린 것 다시(비교 기준) | 약 40% |

→ **화면 추천이 더 좋았다. 엔진 쪽으로 "합치지" 않고, 화면 추천을 게이트 대상으로 바꾼다.** 계획 엔진 세션은 참고 열로 남김.

변형 비교(같은 시간):

| 변형 | 결과 | 채택 |
|---|---|---|
| 복습 상한 40% / **60%** / 80% | 위기 80.6 / **80.9** / 72.7%, 고정 20.0 / **25.2** / 23.4% | 60% 유지(화면에 근거로 적음) |
| 새 문항을 계획 엔진 Δ 순서로 | 81.4% / 25.1% — 차이 없음 | 아니오(복잡도만 늘어남) |
| 시험 전 7일 "밀린 복습 당기기"(복습 몫 60/80/100%) | 몫 60 → 80 → 100%: 80.7 → 77.3 → 70.8% | 아니오 |
| **시험 직전 3일 총정리**: 복습을 예정일 대신 시험일 기억률 낮은 순(복습 몫 그대로) | 87.8 vs 86.2%(부분), 고정 25.2 vs 24.8% | **예** — 예상 점수 계산(outlook `LATE_DAYS` 3)이 가정하는 직전 복습을 추천도 그대로 하게 됨 |
| **과목 진단**: 진단 덜 된 과목 새 문항을 과목당 10개까지 번갈아 | 합격 확률 ±1%p(잡음 범위) | **예** — 예상 점수가 5일 뒤가 아니라 1~2일 만에 나옴 |
| **새 문항 과목 배분**: 한 과목에 몰기 → 합격 확률 기여도(`subjectWeights`) 비례(동트 방식) | 학습자가 앱 경고로 시간을 정하는 실행에서 위기 73.4 → **75.1%**, 망각형 최저 과목 **37 → 55점**(과락 해소), 예상 오차도 작아짐 | **예** |

`session.ts` 정리: A(화면 — 시스템 추천·과목별) / B(계획 엔진 세션 — 게이트 참고) 두 경로를 머리말에 사실대로 적음. 화면은 과목을 일부러 섞지 않는다(5절).

## 3. 게이트 결과(v0.8.0) — docs/engine-gate.md

- **19/19 통과**. 위기 대응형 합격 확률 평균 **앱 75%** · 회차순 40% · 계획 엔진 51%(같은 시간)
- 최저 과목 54점(과락 없음), 미달 시 7일 전 경고 27/27
- 예상 오차: 27번 중 24번 ±4.2점 안(중앙값 1.5점), **망각형 60일만 +7.7~+8.4점**

## 4. 알려진 한계 — 빨리 잊는 학습자의 60일 예상

- 원인 분석(진단 실행): 가상 학습자의 기억은 일부러 FSRS와 다른 모형(지수 망각, 복습 효과 = (1.5 + 8(1−R))·√f). 앱 추천은 예정일(기억률 90%) 무렵에만 복습해 **복습 기록으로는 맞게 보정**되지만(복습 정답 예측 0.763 vs 실제 0.757), 마지막 풀이 뒤 시험일까지의 기억은 모형이 높게 본다(평균 기억률 예측 0.65 vs 실제 0.48).
- 시도: ① 긴 공백 보수 보정 `examRecall`(안정도보다 오래 지나면 멱함수·지수 곡선 평균) — 8.7 → 7.1점, **채택** ② 복습 횟수별 안정도 증가율 g 보정(격자 확장·결합 탐색까지) — 개선 없음, **되돌림** ③ "기록으로 확인된 최장 간격"으로 안정도 상한 — 개선 없음 ④ 시험 직전 복습 몫 확대 — 오차는 줄지만 합격 확률이 낮아짐
- 결정: 게이트 조건 3은 ±5점 유지, **망각형 60일만 ±10점으로 명시**(`KNOWN_FORECAST_GAP`). 합격 가능성에 예상 오차(표준편차 4점)를 넣고, 학습 원리 화면에 "빨리 잊는 사람은 약 8점 높게 예상될 수 있다"고 그대로 적는다.
- 실제 사람의 망각은 멱함수에 가깝다는 것이 FSRS 벤치마크의 결론이라 실사용에서는 덜할 수 있으나, 7단계 실사용 기록으로 다시 확인한다(백로그).

## 5. 화면(v0.8.0)

1. **합격 가능성**(`engine/chance.ts passChance`): 과목당 20문항 이항분포(시험 운) × 예상 오차 N(0, 4점) 다섯 점 평균. 홈 예상 점수 아래, 학습 계획 미리보기, 계산 화면
2. **학습 점검 카드**(`insight.ts`, 홈): 위험·아슬아슬하거나 실제 학습량이 계획의 90% 미만일 때만
   - 최근 실제 학습량: 어제까지 최근 14일(첫 풀이부터, 3일 미만이면 판단 안 함), 문항당 최대 5분, 모의고사 제외, 쉬는 날 포함 평균 ÷ 같은 기간 계획
   - "이 속도면" 예상: 남은 계획(평소 시간·날짜별 시간)을 실제/계획 비율로 줄여 다시 계산
   - 합격에 필요한 평소 하루 시간: 같은 비율로 키워 실제 시험 기준 예상이 여유(과목 ≥ 45·평균 ≥ 65) / 최소(40·60)를 넘는 가장 작은 시간(10분 단위 이분 탐색, 상한 8시간 — 넘으면 "8시간으로도 어렵다, 회차를 더 넣거나 시험일 재고")
   - 상태 판정은 모두 **실제 시험 기준**으로 통일(②)
   - 계산이 무거워(Node 약 0.4초) 홈을 먼저 그린 뒤 채움
3. **예상 점수 계산 보기**(홈 "계산 보기"): ① 시험 문항 구성(같은/변형/처음, 실측 근거) ② 과목별 표(기출 점수 지금→시험일, 처음 보는 문항 정답률 지금→시험일, 시험 예상)와 식 ③ 기출 점수의 시험일 값(FSRS 기억률, 남은 시간 배분, 직전 3일, 전이, 개인 망각 곡선 보정 상태) ④ 합격 가능성 ⑤ 계획과 실제 학습량·필요 시간, 가정과 한계
4. **시스템 추천 화면**: 문항 수 계산식(오늘 계획 분 ÷ 문항당 시간(내 풀이 중앙값 또는 기본 1분 30초) − 오늘 푼 수), 항목별 원리 태그, 과목별 복습·새 문항 표, 접힌 "왜 이렇게 구성했나요?"(복습 60% 근거, FSRS 예정일, 과목 배분·진단, 섞지 않는 이유, 묶음 끝 다시 풀기)
5. **학습 원리**(홈 맨 아래 단추): 인출 연습[Roediger & Karpicke 2006; Dunlosky 외 2013], 피드백[Butler & Roediger 2008], 망각 곡선·분산 학습[Murre & Dros 2015; Cepeda 외 2006], FSRS[Ye 외 2022, Anki 23.10], 약한 과목 먼저(합격 확률 계산), 기출 중심(34회차 실측), 섞어 풀기(Brunmair & Richter 2019 — 어휘 학습에서는 역효과라 강제하지 않음), 예상·경고 방법, 가상 학습자 검증 결과, 한계, 참고 문헌 링크
   - "합격 보장" 표현은 쓰지 않는다
