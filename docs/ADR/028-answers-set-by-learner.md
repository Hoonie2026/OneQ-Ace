# ADR 028 — 정답이 없어도 기출 문항은 모두 문제팩으로, 정답은 학습자가 지정 · 스캔본 문항 최대한 만들기

- 상태: 결정·구현(사용자 2026-11-17) · 생성기 0.5.0-dev.40 · 학습앱 v0.18.0. ADR 024(정답 못 찾은 문항은 뺌)·ADR 026 8(정답 표시가
  없는 PDF는 회차 전체를 만들지 않음)·ADR 027(정답이 그림에 남은 문항은 뺌)을 바꿈

## 배경(사용자)

"정답을 매칭하지 못하더라도 과거 기출문제만 문항별로 생성할 수만 있다면 정답은 학습앱에서 사용자가 지정" — 정답 불일치로 문제팩 생성
자체를 막는 것은 불합리. 교사용 PDF 조건은 안내로 유지. 정답 표시가 지워지지 않은 그림도 기출을 확인할 수 있어 의미가 있음.
2단 구성·쪽을 넘는 문항·중간의 과목명 박스는 대부분의 기출 PDF 형태 — 최대한 문항을 만드는 데 집중.

## 결정

1. **문제팩 형식**: `answer`는 1~5 또는 **null**(정답 미지정), `answerSource`/`answerCheck`에 `none`, flags에 `answer-missing`(정답 없음)·
   `answer-visible`(정답 표시가 그림에 남음)·`user-answer`(학습자가 지정). 생성기·학습앱 검증기 같은 규칙(shared/pack-schema.json)
2. **생성기**: 정답을 못 찾은 문항도 넣음(answer null). 정답 표시가 남은 문항도 넣음(answer-visible). **빼는 것은 문항 그림이 망가진
   경우뿐** — 두 문항이 붙어 읽힘·쪽 머리글이 섞임·비정상적으로 긴 그림·찾지 못한 문항, 현행 출제기준에 없는 과목.
   **회차를 포기하는 것은 문항을 만들 수 있는 문항이 출제기준 문항 수의 절반도 안 될 때뿐**(정답 유무와 무관). 정답 표시가 대부분
   없는 PDF는 끝난 뒤 '정답은 학습앱에서 지정 — 교사용 PDF를 올리면 정답까지'로 안내(조건 2는 안내)
3. **학습앱**: 정답 미지정 문항을 처음 풀 때(보기·모름·쉬움) **[정답 지정하기]** 창 — ①~④·[웹검색으로 확인하기]·[나중에].
   지정하면 그 정답으로 채점, **같은 내용(contentHash)의 다른 회차 문항에도** 반영, 이 문항들의 풀이 기록을 다시 채점,
   설정 `answer:<hash>`에 남겨 **문제팩을 다시 가져와도·백업 복원 뒤에도** 유지. 답한 뒤 [정답 지정하기]/[정답 고치기]
   (정답 확인 필요·내가 지정·정답 표시 남음 문항). [나중에]는 정답 없이 기록(점수에 안 들어감, 다음에 다시 물음).
   정답 미지정 문항은 모의고사에서 뺌(채점 불가)
4. **스캔본 문항 나누기**(철도토목기사 PC OCR 재현):
   - 단 구분을 **쪽마다**(종이 위치가 쪽마다 달라 전체 하나로 잡으면 오른쪽 단 문항번호·보기가 왼쪽 단으로 감 — 2009 21번에 22~26번이 붙음),
     크롭 폭도 쪽마다(`Layout.page_cols`/`col_of`)
   - 1과목 머리말을 못 읽어도 1과목 번호는 시험지 번호 그대로(번호 하나 놓치면 뒤 전부를 순서로 매겨 밀리던 2018)
   - OCR이 번호 앞자리를 빠뜨리거나 잡티로 읽음('13.'→'3.', '21.'→':1.') — 끝자리가 기대 번호(~+3)와 맞고 뒤에 한글 발문이면 그 번호
   - 과목 머리말을 둘 이상 못 읽어 순서로 못 정하면 문항 내용(출제기준 세부항목 낱말)으로 — 2018 3과목 = 응용역학, 4과목 = 옛 과목

## 결과(사용자 PC OCR 그대로 재실행)

철도토목기사 15회차 **모두 문제팩, 1,024문항**(전 dev.39: 10회차 469문항). 회차당 43~79문항(현행 80문항), 정답 미지정 425·
정답 확인 필요 291·정답 표시 남음 47 — 학습앱에서 지정·확인.

## dev.41 · 학습앱 v0.18.1 — 사용자 의견(2026-11-17, PC로 다시 만든 뒤)

### 학습앱: 정답 지정 창 없음, 안내 통일
- 답할 때 정답을 묻는 창(팝업)은 **설계에서 뺌**. 정답 미지정 문항도 그대로 기록('정답 미지정 · 내 답 ②')하고,
  답한 뒤 **[정답 지정하기]**(정답 미지정)·**[정답 고치기]**(정답 확인 필요·내가 지정)를 누르면 보기 번호 단추가 '정답 고르기'(점선)로
  바뀌어 번호를 누르면 정해짐([취소]). 한 번 지정하면 다음부터 [정답 고치기]로
- 안내는 한 모양(노란 상자): '⚠ 정답 미지정 …[정답 지정하기]' / '⚠ 정답 확인 필요 …[정답 고치기]' / '⚠ 내가 지정한 정답 …[정답 고치기]'
- 지정한 정답은 문항 행과 설정 `answer:<hash>`에 남아 **학습 기록 지우기(전체·종목)와 무관하게 유지**, 문제팩 삭제 뒤 다시 가져와도 유지.
  '모두 지우기'·브라우저 초기화로 지워지면 처음처럼(정답 미지정 → [정답 지정하기])

### 생성기: 못 만든 문항 전수 분석 → 복구(사용자 PC OCR 재실행, 철도토목기사 15회차 · 현행 80문항 기준 1,200)
| 원인 | 수단 |
|---|---|
| 스캔본 본문을 40pt~H-30으로 잘라 단 맨 위 머리줄(y 34)·쪽 맨 아래 보기 줄을 버림 | 본문 H×2.2%~H-10, 머리글·꼬리말은 되풀이 안내문·꼬리말·쪽 머리글 걸러내기로 |
| 번호 뒤 '•'·'·', 앞 잡티('•12.') | 문항번호로 받음 |
| 번호 줄 위치 모형이 들여 쓴 줄에 끌림(337 vs 310) | 단의 가장 왼쪽 '번호 줄' x(±8)도 문항 머리 |
| 번호를 '①'·'圈.'·'꿈.'으로 읽음 | 번호 자리(±5)에서 시작, 앞 문항 보기 뒤, 발문처럼('?' 이 줄·다음 줄, 한글 8자 이상)이면 다음 번호 |
| 머리줄을 OCR이 통째로 놓침 | 앞 문항 안에서 'k.' 줄 / 보기 뒤 빈칸 / 단·쪽 바뀜 / 발문 끝 '?' 둘 사이 가장 큰 빈칸 → 나눔(그림은 빈칸부터라 놓친 머리줄도 담김) |
| 순서로 매기다 뒤처진 번호(2014: 12번부터 끝까지 밀림) | 또렷한 번호 n이 나오고 바로 뒤가 n+1·n+2면 다시 맞춤(앞의 순서 매긴 문항은 n-1…) |
| 지문 속 값('0.6h,'·'300.310m'·'.songjs.com')을 문항 머리로 | 순서로 매기는 머리는 번호 뒤 한글 발문일 때만 |
| 그림이 보기 사이에 있는 문항·긴 그림 문항을 '붙은 문항'으로 뺌 | 붙은 문항 = 발문 끝('…은?') 둘이 보기·빈칸을 사이에 둠 |

결과: **1,148문항 / 1,200(95.7%)** — 12·16년 80, 11·13·21·22년 79, 09·19년 78 … 14년 63(머리줄 10개 못 찾음).
남은 것: OCR이 머리줄을 놓치고 위치 단서도 없는 문항 36개, 붙은 문항 14개. 번호를 위치로 찾은 구간은 시험지 번호와 한 칸 어긋날 수 있음(그림은 한 문항).
