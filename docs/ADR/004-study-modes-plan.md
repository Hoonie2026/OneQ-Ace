# 004. 학습 화면 흐름 재정의 — 실기기 2차 요구사항의 단계 배치 (계획)

- 상태: 계획 확정 (2026-10-15, 세션 #3). 구현은 표의 단계에서. **화면 구조는 ADR 008로 변경**(회차별 없앰, 과목별 + 모의고사, 오늘 학습 버튼 → 과목 오늘 추천)
- 관련: 개발기준서 6.4·6.5·7.1·8장, ADR 003

## 배경

실기기 2차에서 "학습 흐름이 직관적이지 않다"는 의견과 함께 목표 흐름이 제시됐다:
자격종목 선택 → 시험일(달력) → 주간 학습 목표 자동 계산, 그리고 학습을 **회차별·과목별·모의고사** 세 가지로 나눠 이력 관리.

## 결정 — 화면 구조

```
홈(종목 선택) ─ D-day · 예상 점수 · 이번 주 목표 · [오늘 학습 시작]
 ├ 회차별   : 회차 목록(미시작 / 진행 중 n/100 / 완료 + 최근 점수), 회독 이력 누적
 ├ 과목별   : 종목의 전 회차를 과목으로 묶음. 문항마다 출제빈도 표시, 동일 > 유사 > 1회 순
 └ 모의고사 : 전 회차에서 과목별 20문항씩 출제, 실제 시험시간, 성적만 이력
```

"오늘 학습 시작"(6.5의 자동 구성 세션)은 세 모드와 별개로 홈의 큰 버튼으로 둔다. 무엇을 풀지 고르기 싫은 사용자를 위한 기본값이다.

## 결정 — 과목 통합 기준 (2026-10-15 추가)

과목별 통합·모의고사·예상 점수는 **과목 번호가 아니라 과목명**으로 묶는다. 번호는 회차 안의 순서일 뿐이다.

- 근거: 출제기준 개편으로 과목 순서가 바뀌거나 과목 수가 줄 수 있다(예: 철도토목기사 5과목 → 4과목). 번호로 묶으면 서로 다른 과목이 섞이고, 없어진 과목이 현행 과목처럼 보인다.
- **묶음 키** = 정규화한 과목명(공백·가운뎃점·괄호 표기 차이 제거).
- **현행 과목** = 그 종목에서 가장 최근 회차 팩의 과목 목록과 과목별 문항 수. 모의고사 출제와 예상 점수·과락 판정은 현행 과목 기준.
- ~~이름 변경은 앱에서 묻고, 폐지 과목은 회차별에만 남긴다~~ → **ADR 005로 변경**: 이름 변경(별칭)과 폐지 과목 제외는 **전처리 단계**에서 종목별 출제기준 프로필로 처리한다. 폐지 과목 문항은 팩에 넣지 않는다. 학습앱은 팩의 과목명을 그대로 따르고 묻지 않는다.
- 4단계 첫 작업: 보유 측량기사 34회차의 과목명·순서·문항 수를 대조해 위 규칙으로 처리되는지 확인. → ✅ 머리말은 34회차 모두 동일. 단 2011년 3회차는 내용이 구기준 과목 구성(ADR 005 추가 절)
- 모의고사 출제 비율(약점 위주 vs 출제빈도 위주 vs 무작위)은 4단계 시뮬레이션으로 정한다. → ✅ 출제빈도 가중 무작위(ADR 006)

## 5단계(5a) 구현 결정 (2026-10-15, 세션 #5, 앱 v0.2.0)

- **오늘 학습·모의고사는 회독과 별개**: 풀이 기록 mode `today`·`mock`. 회차별 진도·이어 풀기·회독 성적에는 넣지 않고(ADR 003 유지), 학습 엔진(FSRS·예상 점수)에는 모두 반영
- 여러 회차에 걸친 묶음은 runs에 `packId = ${종목}-@today|@mock`, `certCode`로 저장(종목 삭제 시 함께 삭제). 성적은 과목명으로 묶어 계산
- 오늘 학습: 엔진 세션 15문항(6.5). 세션 끝 재출제는 "틀린·모름 문항 다시" 버튼으로 같은 종류의 새 묶음을 만든다(같은 문항을 한 묶음 안에서 두 번 풀게 하지 않음). 오늘 학습시간만큼 "오늘 학습 계속"
- 모의고사: 정답을 숨기고 한 문항에 한 번만 답함(바꾸기 없음 — 바꾼 답이 기억 모델에 두 번 들어가지 않게). 시간은 시작 시각부터 흐르고(앱을 닫아도), 제출·시간 종료 시 안 푼 문항 0점으로 판정
- 합격 기준 경고의 "남은 날 매일 ○분으로 바꾸기"는 사용자가 누를 때만 날짜별 학습시간을 채운다(ADR 007)
- 남은 일: **과목별 전 회차 통합 학습(출제빈도순, 과목 반복·성적 이력)** — 5b
