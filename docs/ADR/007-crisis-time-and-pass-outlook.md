# 007. 날짜별 학습시간·합격 기준 경고·합격 확률 기여도 — 4단계 게이트를 위기 대응형 시나리오로

- 상태: 확정 (2026-10-15, 세션 #5). 게이트 통과(`docs/engine-gate.md`)
- 관련: 개발기준서 6.4·6.6·7.1, ADR 006
- 코드: `app/src/engine/minutes.ts`, `outlook.ts`, `plan.ts`, `sim.ts`, `sim.test.ts`

## 배경

세션 #4 게이트는 27회 중 23회 통과였다. 실패는 "하루 60분 고정, 14일 안에 20%짜리 과목을 40점으로" 3회와 예상 오차 1회.
같은 시간에 약한 과목만 푸는 참고 상한도 44~45점이라, **시간 자체가 거의 한계**인 시나리오였다.

사용자가 밝힌 실제 학습 행동이 시나리오 재정의의 근거다(선택지 3의 "근거가 있을 때만"):
- 시험 14일 전에도 합격이 불투명하면 하루 60분이 아니라 **최소 2~3시간**으로 늘린다
- 시험 1~2일 전에는 **연차를 내서라도** 부족한 부분을 공부한다

사용자 결정: 선택지 1(엔진 보완)과 3(시나리오 학습시간 재정의)을 병행 — 위기 대응형 시나리오, 날짜별 학습시간, 합격 기준 경고, 과목 배분 보완.

### 왜 1·5·7이 필요했나(시뮬레이션에서 드러난 것)

- 위기 대응으로 시간을 3배 늘리자 엔진이 **회차 순서대로 푸는 것보다 못해졌다**(균형형 30일: 62 vs 65점). 원인은 "예정된 복습은 전부 필수" 규칙:
  개인 망각 곡선이 빠르게 잡히면 거의 모든 문항이 이번 주 복습 예정이 되고, 마지막 주에는 신규가 금지라 **늘린 시간이 이미 잘 기억하는 문항 복습으로만** 찼다
  (마지막 주 계획이 가용량보다 적어 학습자가 시간을 남기기도 함). 5번으로 해소 — 같은 시간에서 합격 확률이 비교 기준 이상
- 평균 점수 비교는 **과락을 감수하고 강한 과목만 올린 쪽**이 이긴다. 과락형 14일 위기 대응: 회차순은 평균 63.6이지만 약한 과목 41점(합격 확률 55%),
  엔진은 평균 65.2·약한 과목 68점(87%). 앱의 목적(한 번에 합격)에 맞는 척도는 합격 확률이다
- 균형형은 과목 차이가 없어 회차순이 거의 최선이다. 시드마다 엄격히 비교하면 76% vs 79%처럼 잡음 수준 차이로 갈려서 시나리오 평균·3%p 허용으로 정했다

## 검토했으나 보류

- 과락 집중 모드(과락선 + 여유/2 아래 과목이 있으면 신규를 그 과목에서만): 고정 60분 14일 과락형은 42~44점으로 해소되지만, 덜 본 강한 과목의 예상 오차가 5점을 넘고 평균이 비교 기준보다 낮아짐
- 신규 문항 Δ를 "익힐 때까지의 기대 이득 ÷ 비용"으로(근시안 Δ 대체): 위기 대응형에서 차이 없음
- 전체 첫 풀이 정답률을 과목 평균의 평균으로(약한 과목을 많이 풀면 전체 평균이 끌려 내려가는 문제): 개선 없음
- 고정 시간형 14일 과락형(하루 60분)의 과락: 참고 상한이 44~45점이라 배분만으로는 여유가 없다. **엔진은 대신 D-12부터 합격 기준 경고를 내고, D-7에는 합격까지 하루 575~760분이 필요하다고 알린다** — 이 경고를 보고 시간을 늘리는 것이 위기 대응형 시나리오

## 영향

- 5단계 홈: 합격 기준 경고 카드(`engineOutlook`) — 상태, 과목별 지금/투영 점수, "과락만 벗어나려면 하루 ○분 / 합격까지 하루 ○분", 남은 날 학습시간 지정(연차·집중일)
- 오늘 학습: 날짜별 학습시간으로 오늘 문항 수(`todayTarget`)가 정해진다 — 15문항 세션을 몇 번 이어 갈지
- `npm run gate` 약 85초(위기 대응형 9시나리오 + 고정 시간형 참고 9시나리오, 각 3시드)
- 개발기준서 6.4(과목 가중치·필수 복습·마지막 주)·6.6(시나리오 학습시간·게이트 조건)·7.1(날짜별 학습시간) 표를 이 ADR에 맞게 고칠 것
