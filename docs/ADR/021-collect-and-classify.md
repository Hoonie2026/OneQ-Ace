## 1. 수집 — 자동 2가지 + 직접 올리기

사용자 결정(2026-10-22):
- **계정·API 키·외부 프로그램 설치 없음.** 큐넷 OpenAPI(공공데이터포털 인증키) 쓰지 않음
- 한 번에 **종목 하나**: 검색창에 종목명(별칭 허용, 예: "측량기사") → 아래 두 가지를 그 자리에서 가져옴
  1. **큐넷 출제기준 자료실**에서 그 종목의 **현행** 출제기준 첨부(HWP) → 과목명·주요항목·세부항목·세세항목. 게시글 제목의 적용 기간 "(2025.1.1.~2027.12.31.)"으로 현행을 고름. 쓸 때마다 받아 오므로 기준이 바뀌어도 앱 갱신 불필요
  2. **comcbt.com**의 종목 게시판에서 기출 목록 → 사용자가 회차 범위를 골라 받기(교사용 PDF)
     - 게시판 주소는 종목마다 짧은 코드(`/xe/dv` 측량, `/xe/nj` 건설안전, `/xe/n1` 토목). 메인 페이지 메뉴를 읽어 "종목명 → 게시판"을 그 자리에서 만듦(미리 넣어 두지 않음)
     - 게시글 제목이 통일됨: "측량및지형공간정보기사 필기 기출문제 및 CBT 2018년 03월 04일(1회)" → 시행일·회차
     - robots.txt는 게시글 접근 허용, 목록의 `page=`·검색·정렬 변수 주소는 막음 → 목록 넘기는 방식은 PC에서 실제 화면 확인 뒤 정함
     - 사용자 판단: 사이트 구조는 10년 넘게 그대로, 공개 자료, 개인이 한 종목씩 받으므로 트래픽 문제 없음
- comcbt에 없는 종목(예: 철도토목기사 — 기능사·산업기사만 있음)·법령 문제가 많은 종목은 **사용자가 직접 구해 올림**. 앱이 먼저 찾고, 없을 때만 직접 올리기 안내
- **HWP·DOC 기출을 PDF로 바꾸는 기능은 만들지 않음**(LibreOffice+Java 필요 → 사용자 기각). "한글/워드에서 PDF로 저장" 안내만. 출제기준 HWP는 PDF로 바꾸지 않고 글자를 직접 읽음

## 2. 판정은 파일명이 아니라 내용에서

- 종목·시행일·회차·과목은 **문서 내용**에서 읽는다(comcbt 파일도 같음, 게시글 제목은 대조용)
- 글자 있는 PDF는 글자를 바로, 글자가 없거나 깨진 페이지는 OCR(페이지마다 자동, 사용자에게 묻지 않음). 직접 올린 파일은 스캔본일 가능성이 높아 **OCR은 기본 경로**
- **시행일을 못 찾으면 묻지 않고 자동 지정** "0000년 nn회"(nn = 같은 종목 안에서 올린 순서)
  - 영향: 팩 스키마(연도 1990~2100·date 필수)에 "시행일 모름" 표시 추가, 앱의 최신 회차 순서 계산에서 맨 뒤로

## 3. 직접 올리는 기출 조건 — 셋만

1. 한 파일 = 한 회차
2. 정답이 파일 안에 있을 것(보기에 표시 또는 정답표)
3. 알아볼 수 있는 스캔 품질(사진보다 스캔, 심하게 기울지 않게)

샘플 이미지와 함께 안내하고, 넣는 즉시 검사해 빠진 조건을 알려 준다. 뺀 조건: 파일명 규칙, 글자 선택되는 PDF, 과목 머리말, 시행일 표기.
스캔본 정답 표시(칠한 번호·형광펜) 인식이 가장 약한 고리 → 확신 낮은 문항만 검수 창에서 정답을 고르게 함.

## 4. 과목별 학습 = 단원별 + 유형별 (사용자 결정 2026-10-23)

### 4.1 단원별
- 단원 = 출제기준 **주요항목**(화면). 전처리기가 문항마다 배정, 내부적으로 **세부항목**까지 배정(4.3 묶음에 씀)

### 4.2 유형별 — 탭 셋, 필터 셋
| 탭 | 판정 | 비고 |
|---|---|---|
| [계산 정복] | 숫자·단위·수식, 보기 넷이 수치 | 겹치면 이것 먼저 |
| [기준·법령 몰아보기] | 법령 낱말 사전 + 출제기준 세부항목의 법령·기준 이름 + 법규 과목 | 둘째 |
| [개념·실무] | 나머지 | 처음 제안의 "개념"과 "실무"를 **합침**(경계가 흐리고 풀이 행동이 같음) |

필터: **순서·절차만**(발문 "순서로 옳은 것"·ㄱㄴㄷ·화살표) / **빈출만**(여러 회차에 나온 묶음, 앱에서 계산) / **내가 자주 틀린 것**(개인 기록).
문항이 없는 탭은 숨김. 화면 선택은 "과목 → 단원별/유형별" 두 번까지.

### 4.3 묶음 학습 (사용자 제안 세 가지)
- 관계: ADR 015 9절(v0.10.4)은 "계산 문제 자동 판정·전처리기의 계산 문제 분류를 하지 않는다"였다 — 그때 목적은 계산기 **자동 열기**(사용자가 기각). 이번은 **유형별 학습 묶음**이 목적이라 다시 도입하되, 계산기 자동 열기는 되살리지 않는다(사용자 결정 2026-10-23에 따름)
- **계산**: 같은 세부항목 + 계산형 + 핵심 용어(편평률·클로소이드 등) = "같은 공식" 묶음. 지금 글자 2-gram 유사도는 숫자만 바뀐 같은 공식 문제를 놓침(편평률 0.55, `similar.ts` 주석) → 유사도로 묶지 않음
- **법령**: 법령 이름 + 핵심 용어 묶음 → **묶음 단위로 한 번에** [현행 법령 찾아보기]/웹검색(ADR 019 2단계 확장). "출제 당시 기준" 안내 — 앱은 현행 기준으로 정답을 자동 판정하지 못함. 조항 번호는 지문에 거의 없어 조항 단위로는 못 묶음
- **절차**: 순서형 발문 + 같은 세부항목
- 묶음을 마치면 "섞어서 풀기 → 시스템 추천"으로 이어 줌. 근거: 몰아 풀기는 처음 익히기에, 섞어 풀기는 실제 시험(어떤 공식을 쓸지 고르기)에 유리 — 중1 수학 9주, 섞기 72% 대 몰기 38%(Rohrer·Dedrick·Burgess 2014)

### 4.4 뺀 것 (사용자 결정 2026-10-23)
- 2차 "진위 / 단답 / 복합 조건" 구분을 화면에서 뺌(학습 효과 낮음, 복합 조건은 판정도 어려움). 순서·조합만 필터로 남김
- 3차 "신규 출제(개정 반영)"·"고난도·함정" 태그 뺌 — 개정은 API 없이 확인 불가, 한 번 나온 신규 문제의 재출제 보장 없음, 고난도는 전체 응시자 정답률이 없어 추정일 뿐. 대신 개인 "내가 자주 틀린 것"
- "부정형 발문 강조"는 결정 안 함(선택 사항, 풀이 화면 글자 강조 정도) — PREP-PLAN-v0.5 보류 목록

### 4.5 처리 분담·검수
- 전처리기(문항 글자 필요): `unit`(주요항목)·세부항목·유형(탭)·순서형 여부 + 확신도. 팩 oqp/1에 **선택 칸**으로(옛 팩도 읽힘, 없으면 단원·유형 화면 비활성)
- 앱(여러 회차·개인 기록 필요): 빈출, 내가 자주 틀린 것
- **분류는 검수 대상이 아님**(정답만 검수). 틀린 분류는 앱 [이 문제 분류가 이상해요] 같은 가벼운 길을 검토
- 화면에 내놓기 전 정확도 실측: **계산 분류는 토목기사 응용역학**(사용자 지정, PC에서 PDF 제공), 단원 배정은 측량 1과목, 법령은 건설안전 1과목 — 정답표는 Claude가 만듦
