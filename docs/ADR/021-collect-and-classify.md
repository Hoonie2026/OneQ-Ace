## 2. 판정은 파일명이 아니라 내용에서

- 종목·시행일·회차·과목은 **문서 내용**에서 읽는다(파일명은 쓰지 않음)
- 글자 있는 PDF는 글자를 바로, 글자가 없거나 깨진 페이지는 OCR(페이지마다 자동, 사용자에게 묻지 않음). 직접 올린 파일은 스캔본일 가능성이 높아 **OCR은 기본 경로**
- **시행일을 못 찾으면 묻지 않고 자동 지정** "0000년 nn회"(nn = 같은 종목 안에서 올린 순서)
  - 영향: 팩 스키마(연도 1990~2100·date 필수)에 "시행일 모름" 표시 추가, 앱의 최신 회차 순서 계산에서 맨 뒤로
- **구현(B2, 2026-10-24 세션 #12)** `oneq_prep/examinfo.py`:
  - 읽는 곳: 첫 쪽 위 35%(머리말)·마지막 쪽 끝(꼬리말). comcbt "종목 ◐ YYYY년 MM월 DD일 필기 기출문제 ◑ … comcbt" → 시행일·출처(public-pbt), 한솔 "24토목기사 … 2024년3회CBT 대비 … 경향문제" → 연도·회차만, 출처 "한솔아카데미"(other, "기출이 아니라 … 유형문제"). 그 밖에 "YYYY년 MM월 DD일"·"YYYY.MM.DD"·"YYYY년 (제)N회"
  - 회차: 문서에 "N회"가 있으면 그것, 없으면 **시행월**(기사: 3월까지 1회 · 4~6월 2회 · 7월 이후 3회, 2020년 6월 1·2회 통합 · 8월 3회 · 9월 4회). 2003~2022 건설안전·측량·토목 시행일 모두에서 지금까지 만든 팩 회차와 같음 → 팩 이름 그대로. (v0.4는 함께 올린 파일 사이 순서였음 — 한 회차만 올리면 1회로 잘못 붙음, 예: 2022-04-24 → 1회)
  - 표기: 연도·회차만 알면 date "YYYY-00-00" + `dateUnknown`, 아무것도 모르면 연도 0 · date "0000-00-00" · packId "종목-0000-nn"(nn은 같은 종목에서 올린 순서, 출력 폴더 `review/unknown-dates.json`에 파일 내용 해시로 기록해 다시 처리해도 같은 번호). 앱 표시 "0000년 n회"·"시행일 모름", 날짜 정렬에서 맨 뒤. 시행일 모름은 옛 기준 재배정 대상으로 보지 않음
  - 문서의 종목명이 고른 종목과 다르면 검수 필요("이 파일은 '…' 문서로 보입니다"). 산업기사 등 기사가 아닌 등급은 회차 규칙 미확인(표본 없음)

## 3. 직접 올리는 기출 조건 — 셋만

1. 한 파일 = 한 회차
2. 정답이 파일 안에 있을 것(보기에 표시 또는 정답표)
3. 알아볼 수 있는 스캔 품질(사진보다 스캔, 심하게 기울지 않게)

샘플 이미지와 함께 안내하고, 넣는 즉시 검사해 빠진 조건을 알려 준다. 뺀 조건: 파일명 규칙, 글자 선택되는 PDF, 과목 머리말, 시행일 표기.
스캔본 정답 표시(칠한 번호·형광펜) 인식이 가장 약한 고리 → 확신 낮은 문항만 검수 창에서 정답을 고르게 함.

## 4. 과목별 학습 = 단원별 + 유형별 (사용자 결정 2026-10-23)

### 4.1 단원별
- 단원 = 출제기준 **세부항목**(사용자 결정 2026-10-24, 처음 정한 주요항목에서 바꿈). 주요항목은 세부항목을 묶는 머리글로만 표시. 전처리기가 문항마다 세부항목을 배정(4.3 묶음에도 같은 값)
- 바꾼 이유(토목기사 현행 출제기준 실측): 과목당 주요항목이 1~4개뿐 — 응용역학 1(세부 10), 철근콘크리트및강구조 1(세부 3), 수리학및수문학 2(10), 토질및기초 2(13), 상하수도공학 2(6), 측량학 4(10), 합계 세부 52·세세 183. 주요항목이면 단원 화면이 1~2칸
  - 세부 수 정정(2026-10-24, A1 파서): 처음 적은 11·12·15·7·12는 쪽이 바뀔 때 첫 줄에 되풀이되는 세부항목을 두 번 센 값. 세부·세세항목 번호가 1부터 끊김 없이 이어지는 것으로 확인
- 칸이 많아진 만큼 배정 정확도를 엄격히 실측(4.5)

### 4.2 유형별 — 탭 셋, 필터 셋
| 탭 | 판정 | 비고 |
|---|---|---|
| [계산 정복] | 숫자·단위·수식, 보기 넷이 수치 | 겹치면 이것 먼저 |
| [기준·법령 몰아보기] | 법령 낱말 사전 + 출제기준 세부항목의 법령·기준 이름 + 법규 과목 | 둘째 |
| [개념·실무] | 나머지 | 처음 제안의 "개념"과 "실무"를 **합침**(경계가 흐리고 풀이 행동이 같음) |

필터: **순서·절차만**(발문 "순서로 옳은 것"·ㄱㄴㄷ·화살표) / **빈출만**(여러 회차에 나온 묶음, 앱에서 계산) / **내가 자주 틀린 것**(개인 기록).
문항이 없는 탭은 숨김. 화면 선택은 "과목 → 단원별/유형별" 두 번까지.

### 4.3 묶음 학습 (사용자 제안 세 가지)
- 관계: ADR 015 9절(v0.10.4)은 "계산 문제 자동 판정·전처리기의 계산 문제 분류를 하지 않는다"였다 — 그때 목적은 계산기 **자동 열기**(사용자가 기각). 이번은 **유형별 학습 묶음**이 목적이라 다시 도입하되, 계산기 자동 열기는 되살리지 않는다(사용자 결정 2026-10-23에 따름)
- **계산**: 같은 세부항목 + 계산형 + 핵심 용어(편평률·클로소이드 등) = "같은 공식" 묶음. 지금 글자 2-gram 유사도는 숫자만 바뀐 같은 공식 문제를 놓침(편평률 0.55, `similar.ts` 주석) → 유사도로 묶지 않음
- **법령**: 법령 이름 + 핵심 용어 묶음 → **묶음 단위로 한 번에** [현행 법령 찾아보기]/웹검색(ADR 019 2단계 확장). "출제 당시 기준" 안내 — 앱은 현행 기준으로 정답을 자동 판정하지 못함. 조항 번호는 지문에 거의 없어 조항 단위로는 못 묶음
- **절차**: 순서형 발문 + 같은 세부항목
- 묶음을 마치면 "섞어서 풀기 → 시스템 추천"으로 이어 줌. 근거: 몰아 풀기는 처음 익히기에, 섞어 풀기는 실제 시험(어떤 공식을 쓸지 고르기)에 유리 — 중1 수학 9주, 섞기 72% 대 몰기 38%(Rohrer·Dedrick·Burgess 2014)

### 4.4 뺀 것 (사용자 결정 2026-10-23)
- 2차 "진위 / 단답 / 복합 조건" 구분을 화면에서 뺌(학습 효과 낮음, 복합 조건은 판정도 어려움). 순서·조합만 필터로 남김
- 3차 "신규 출제(개정 반영)"·"고난도·함정" 태그 뺌 — 개정은 API 없이 확인 불가, 한 번 나온 신규 문제의 재출제 보장 없음, 고난도는 전체 응시자 정답률이 없어 추정일 뿐. 대신 개인 "내가 자주 틀린 것"
- "부정형 발문 강조"는 결정 안 함(선택 사항, 풀이 화면 글자 강조 정도) — PREP-PLAN-v0.5 보류 목록

### 4.5 처리 분담·검수
- 전처리기(문항 글자 필요): `unit`(세부항목, 주요항목은 출제기준에서 따라옴)·유형(탭)·순서형 여부 + 확신도. 팩 oqp/1에 **선택 칸**으로(옛 팩도 읽힘, 없으면 단원·유형 화면 비활성)
- 앱(여러 회차·개인 기록 필요): 빈출, 내가 자주 틀린 것
- 검수는 학습 엔진 필수 정보(문항 경계·정답·과목)의 **의심 문항만**(6절). 단원·유형은 전처리기에서 사람이 고르지 않는다
- **단원 미정 → 학습 중 고르기**(사용자 결정 2026-10-24, 처음 정한 "전처리기에서 몰아 고르기"를 대체): 확신 있는 단원만 팩에 확정하고, 나머지는 "미정" + 자동 판정 **후보 3개**(`unitCandidates`). 앱은 미정 문항에만, **답한 뒤** 결과 화면 작은 줄로 "이 문제 단원은? [후보1] [후보2] [후보3] [모르겠음]"을 묻는다 — 한 문항 한 번, 건너뛰어도 그만, 설정에서 끌 수 있음. 고른 단원은 그 기기의 "내가 고른 단원"(바꿀 수 있음, 백업에 포함, 같은 문항 묶음에 함께 적용). 후보가 없는 문항(근거 낱말 0)은 묻지 않고 미정. 자동 확정 문항에는 묻지 않음
  - 근거: 후보 3개 안에 정답이 드는 비율 — 토목 응용역학 89%, 측량 1과목 78%(미정 문항 기준). 전체 목록(10~12개)에서 고르게 하지 않는 이유: 초보자는 문제를 겉모양으로 분류하는 경향(Chi·Feltovich·Glaser 1981). 분류 활동 자체는 문제 해결 학습에 쓰이는 방법
  - 단원별 화면: 단원 칸 + "미정" 칸. 미정 문항도 시스템 추천·유형별 학습에는 그대로 나옴
- 화면에 내놓기 전 정확도 실측: **계산 분류는 토목기사 응용역학**(사용자 지정, PC에서 PDF 제공), 단원(세부항목) 배정은 측량 1과목, 법령은 건설안전 1과목 — 정답표는 Claude가 만듦

### 4.6 C1 구현·C2 실측 (2026-10-24, 세션 #12)
- 구현 `oneq_prep/classify.py`: 단원 = 출제기준 세부·세세항목 낱말 + `standards/unit-keywords.json` 보충 낱말(종목·과목별 교과 용어, "!" = 강한 낱말) — 단원마다 드문 낱말일수록 무게, 더 긴 낱말 안의 짧은 낱말은 버림("부정정보" 안 "정정보"). 유형 = 보기가 수치·수식이고 주어진 값(숫자·그림·식)이 있으면 계산, 주어진 값 없이 숫자를 고르면(최소 위성 수·궤도 경사각) 외우는 문항이라 개념. 확신 = 점수 1.5 이상 · 둘째 단원의 2배 이상
- 팩: 문항 `unit`(확신 있거나 사람이 고른 것만, 없으면 미분류)·`qtype`·`sequence`·`classifyUnsure`, 과목 `units`(id·주요·세부) — 모두 선택 칸(옛 팩·옛 앱 그대로). 검수 파일 `units`·`types`로 사람이 고름. 팩 판 기본 3
- 실측(정답표 `preprocessor/tests/fixtures/classify/`, 사람 분류는 Claude):

| 표본 | 유형 정확도 | 단원 정확도(전체) | 단원 자동 확정 비율 · 그중 정답 |
|---|---|---|---|
| 토목 응용역학 2020~2022 160문항 — 보충 낱말을 문항을 보며 적음(낙관적) | 98.8% | 93.1% | 84% · 97.8% |
| 측량 1과목 2019-3~2022-1 160문항 — **맹검**(보충 낱말을 문항 보기 전에 적음) | 95.0% | 71.9% | 61% · 88.8% |
| 보충 낱말 없는 과목(토목 2022-2 실제 팩: 측량학·수리·철콘·토질·상하수도) | — | — | 20~60% |

- 읽기: **유형(계산 탭)은 바로 쓸 만함.** 단원은 보충 낱말이 있는 과목에서 자동 확정분의 정답률이 높고(89~98%), 나머지(40%)는 몰아 고르기 몫이 큼 — 과목당 회차마다 약 8문항, 31회차면 과목 하나에 약 250문항. 보충 낱말 없는 과목은 자동 확정이 20~60%
- 못 정한 문항 처리 → 4.5 "학습 중 고르기"로 결정(2026-10-24). 실제 토목 2022-2 팩: 120문항 중 확정 66 · 미정+후보 39 · 미정(후보 없음) 15
- 남은 결정: 단원별 화면을 내놓을 기준선(PREP-PLAN 3절) — **C3 가정(2026-10-24, 사용자 답 없음): 모든 과목에 켠다.** 미정 칸과 학습 중 고르기가 오분류를 흡수하고, 단원 정보가 없는 옛 팩은 안내만 보임. 사용자가 기준선을 정하면 과목별로 숨기는 것만 더하면 됨

### 4.7 C3 앱 구현 (2026-10-24, 세션 #12)
- `app/src/units.ts`: 동일 문항 묶음(엔진 `bank.items`) 단위로 단원·유형을 모음 — 같은 묶음 안 아무 문항이든 단원이 있으면 묶음 전체가 그 단원(옛 회차도 새 팩 단원을 따름). 학습자가 고른 단원은 설정 `unitPicks:<종목>`(묶음 키 → 단원 id, "?" = 모르겠음) — 백업에 함께 들어감

## 6. PDF 처리 단계 (사용자 요구 2026-10-23)

- 입력은 사용자가 올린 PDF 목록(끌어다 놓기·파일/폴더 추가). **출처 자동**: 내용에서 판별(예: comcbt 문서의 머리말·안내문 → "comcbt"), 모르면 "직접 올림" — 묻지 않음
- 페이지마다 글자/스캔 판정(2절) → 파일 줄에 [글자]/[스캔]/[섞임]
- 파일마다 **진행 막대** + 지금 단계(읽기 → 문항 나누기 → 정답 → 분류 → 팩). **끝난 파일을 누르면 결과 화면**: 과목별 문항 수, 정답 상태, 유형 분포, 문항 미리 보기 몇 개, 의심 n건이면 [확인하기]
- **검수는 앱이 의심한 것만**(모든 문항 검수는 실사용 범위 밖 — 사용자). 사용자 개입 = "학습 로직에 필요한데 자동 처리 못 한 정보"(사용자 정의)
  - 필수 → 의심 검수. 의심 기준(초안, 구현·실측 때 조정): 정답 못 찾음 / 보기 표시와 정답표가 다름 / 보기 수 이상 / 과목 문항 수가 출제기준과 다름(누락·경계 오류) / OCR 확신 낮음 / 정답 표시 지움 잔존 / 구기준 과목 재배정 확신 낮음
  - 검수 화면: 의심 문항만 차례로, 문항 그림 + 원본 쪽 + 고를 것 하나(정답 1~4 / 빼기). 건너뛰면 정답 모르는 문항은 빼고 팩
  - 선택(단원·유형) → 4.5
  - 시행일 자동 지정("0000년 nn회")은 알림만
- **입력 칸 없앰**: v0.4.0의 만든 사람·저장 폴더·원본 출처·문제 종류·처리 속도 → 모두 자동(팩 스키마 필수 `preparedBy`는 "원큐합격 전처리기 v0.5"로 자동, 저장 폴더는 기본 폴더, 처리 속도는 코어−1)

## 7. 기기로 옮기기·통합 배포 (사용자 결정 2026-10-23)

- **전처리기에서 학습앱으로 직접 보내는 계획은 모두 폐기**: PC 학습앱에 localhost로 바로 넣기, 같은 Wi-Fi 폰에 QR로 보내기, 카카오톡 보내기 도우미, PC 학습앱 유무 감지. 전처리기는 팩 파일을 기본 폴더에 저장하고 그 폴더를 보여 주는 데까지. 옮기기는 사용자가 직접(W4)
- 배경 사실(사용자에게 설명함): 학습앱은 서버·계정 없이 기기마다 브라우저 안에 저장 → PC↔폰 어느 쪽으로도 팩이 저절로 옮겨지지 않음. 풀이 기록은 백업 파일로 합칠 수 있으나(ADR 002·015) 백업에 문항·그림이 없어 **팩은 기기마다 넣어야 함**. iPhone은 Safari와 홈 화면 앱도 따로
- **통합 배포 = 주소 하나**: 앱 주소(GitHub Pages) 하나로 배포. PC로 열면 [전처리기 받기] + [이 PC에 학습앱 설치], 폰으로 열면 앱 설치. 전처리기 첫 화면에 "폰에 앱 설치" QR(앱 주소를 보여 줄 뿐, 팩 전송 아님)
- 폐기: 전처리기 설치에 학습앱을 넣는 방안(B), 전처리기를 웹앱에 흡수(불가 — 큐넷 수집·OCR)
- 남은 걸림: 서명 안 된 exe의 "Windows의 PC 보호" 경고 — 사내 IT 배포 시스템 / Microsoft Store(MSIX) / OV 인증서(연 수십만 원, 바로 해제 안 됨). 먼저 PC-TODO P14

## 8. 팩 단위 = 종목 묶음 (사용자 2026-10-24, 조건부)

사용자: 편의상 종목별 묶음이 유리, 단 ① 이미 팩이 있는 종목에 회차를 더 넣을 때 기존 팩에 영향 ② 묶음과 회차별 가져오기의 지연 차이가 없어야 함.

- 묶음은 **포장만** 하나로: 안에는 지금처럼 회차별 팩(packId = 종목-연도-회차)이 들어 있고, 앱은 펼쳐서 회차마다 같은 길로 가져온다(`pack/bundle.ts` → `importPackFile`)
- ① 추가: 기존 팩·기록에 영향 없음 — 같은 packId·같은 버전·같은 내용(파일 해시)은 **조용히 건너뜀**("이미 있는 같은 팩 n개는 건너뜀(학습 기록 그대로)"), 새 회차만 들어감. 버전이 높으면 교체하고 기록은 이어짐(ADR 002). 남은 틈: 같은 버전인데 내용이 다르면 회차마다 "바꿀까요?"가 뜸 → **전처리기는 같은 회차를 다르게 만들면 packVersion을 올린다**(규칙, 구현 때). 추가할 때 전처리기는 이번에 새로 만든 회차만 묶음에 넣는 쪽을 기본으로(파일이 작아짐)
- ② 지연: 지금 앱은 묶음 전체를 메모리에 한 번에 푼다(`unzipSync`) → 큰 묶음(건설안전 59회차 ≈ 150MB 추정, 회차당 약 2.5MB)은 폰에서 멈춤·메모리 부족 위험. 대책: 앱은 묶음 안 팩을 **하나씩 꺼내 바로 가져오기**(진행 창은 지금처럼 회차별 표시), 전처리기는 묶음 안 팩을 다시 압축하지 않음(이미 압축됨). 실측으로 회차별 가져오기와 시간 비교 → PC-TODO P16. 문제가 남으면 묶음을 크기 단위로 나눔

## 검토한 대안
- 큐넷 OpenAPI를 빌드 때 호출해 내장: 종목 수천 개를 미리 넣고 기준 바뀔 때마다 재배포해야 함 → 사용자 기각(쓸 때 받아 오는 쪽)
- 웹 전반에서 기출을 "알아서" 찾기: 결과 불안정 → comcbt 한 곳 + 직접 올리기(2026-10-22) → comcbt 자동 수집도 폐기, 직접 올리기만(2026-10-24)
- 3차원 다면 분류(1차 4종 × 2차 4종 × 3차 태그 3종) 전체: 4.4 이유로 축소
