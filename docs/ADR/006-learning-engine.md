# 006. 학습 엔진 구현 결정 — 동일 문항 키, 개인 망각 곡선, 과목 진단, 필수 복습 하한

- 상태: 확정 (2026-10-15, 세션 #4). 게이트는 세션 #5에서 통과 — **8·9·10번과 과목 가중치는 ADR 007이 바꿨다**(복습 Δ 경쟁, 마지막 주 신규 Δ 경쟁, 합격 확률 기여도 가중)
- 관련: 개발기준서 4.2·6.2~6.6, D4(ts-fsrs), ADR 002·004·005
- 코드: `app/src/engine/` (순수 함수 + `load.ts`만 DB를 읽음)

## 배경

기준서 6장 공식을 그대로 구현해 가상 학습자 시뮬레이션(6.6)을 돌리자 세 가지가 드러났다.

1. **동일 문항이 안 잡힌다.** 팩의 `contentHash`는 문항 번호("39.")까지 넣어 해시해서, 다른 회차의 같은 문항도 값이 다르다.
   측량 34회차(3,400문항) 실측: contentHash 일치 13쌍뿐, 번호·띄어쓰기·보기 순서를 무시하면 **281묶음·592문항**.
2. **FSRS 기본 망각 곡선은 꼬리가 길다**(안정도 0.2일짜리도 14일 뒤 52%). 학습자가 이보다 빨리 잊으면 예상 점수가 최대 16점 높게 나오고,
   복습의 가치가 낮게 계산돼 복습이 전부 밀리며, 그러면 보정할 복습 자료도 안 생긴다.
3. **과목 실력 추정이 초반에 크게 흔들린다**(첫 풀이 10건이면 ±15%p). 운 좋게 높게 잡힌 과목은 다시 풀 기회가 없어 계속 소외된다.

## 결정

| # | 결정 | 기준서 대비 |

| 1 | **학습 단위 = 동일 문항 묶음**(과목별). 키 = 문항 번호·공백·부호 제거 + 보기 순서 무시. 한 회차에서 푼 기억이 다른 회차의 같은 문항에도 적용되고, 묶음 크기 = 출제빈도. contentHash는 기록 재연결(ADR 002) 용도로 그대로 둔다 | 4단계 계획(contentHash) 변경. 전처리기 변경 없음 |
| 2 | cards 테이블은 쓰지 않고 **원장(attempts)에서 매번 재생**. 3,400문항·3,000건 기준 Node 230ms. 캐시는 7단계 실측 후 | 4.2 "cards = 파생값"의 구현 방식 |
| 3 | 같은 날 다시 푼 기록은 카드에 반영하지 않음(세션 끝 재출제는 오류 교정). `enable_short_term: false`, `enable_fuzz: false` | 6.2 보완 |
| 4 | **개인 망각 곡선**: 복습 풀이 30건부터 안정도 배율 k(0.1~4)와 곡선 감쇠 d(FSRS 기본 0.154~3)를 로그 손실 최소로 격자 탐색. 예상 점수·복습 예정일에 적용 | 6.2 보완(FSRS 매개변수 최적화의 가벼운 대체) |
| 5 | 학습한 문항의 시험일 정답 확률 = r(T) + (1 − r(T)) × 미학습 정답 확률. 잊어도 처음 보는 문항만큼은 맞힌다고 본다 | 6.3 보완(r(T)만 쓰면 푼 뒤 잊은 문항이 처음 보는 문항보다 낮게 계산됨) |
| 6 | 미학습 정답 확률 = 과목 첫 풀이 정답률을 전체 첫 풀이 정답률 쪽으로 당긴 값(가상 관측 10건). 전체는 0.25 쪽으로. 계획에는 1 표준오차를 뺀 보수적 값 | 6.3 "10건 미만이면 0.25"를 연속적으로 |
| 7 | **과목 진단**: 과목마다 첫 풀이 15건이 될 때까지 그 과목 신규를 먼저(과목을 번갈아, 가용량의 절반까지) | 6.4 추가 |
| 8 | **필수 복습 하한**: R + U > C여도 가용량의 30%는 복습(Δ 큰 순)에 먼저 준다 | 6.4 보완(Δ만으로 고르면 초반에 복습이 전부 밀림) |

| 10 | 마지막 주 신규 금지의 예외: **과락 위험 과목은 마지막 주에도 신규 허용** → ADR 007에서 마지막 주 신규도 Δ 경쟁으로 일반화 | 6.4 변경(14일 시나리오에서 과락이 남음) |

## 검토했으나 보류
