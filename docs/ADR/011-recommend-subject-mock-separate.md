# 011. 오늘 학습 목표 아래 "시스템 추천 학습"·"과목별 학습", 모의고사는 따로 — 점수는 학습 결과만, 진도율 대신 점수

- 상태: 확정 (2026-10-18, 세션 #6, 앱 v0.6.0)
- 관련: ADR 008·009·010, 실기기 v0.5.0 의견
- 코드: `engine/session.ts`(`candidates`·`compose`·`REVIEW_SHARE`), `engine/load.ts`(모의고사 제외), `engine/exam.ts`(`TRANSFER`·`projectedRate`),
  `coach.ts`(`examViews` 학습량 반영 예상, `todayPlan` 구성 내역), `ui/CoachCard.tsx`·`RecommendView.tsx`(신규)·`SubjectList.tsx`·`Home.tsx`·`PlanSetup.tsx`

## 배경 (실기기 v0.5.0)

1. 학습계획을 늘려도(매일 1시간 → 3시간, 5시간짜리 날 3일 추가) **시험일 예상 점수가 그대로**.
2. 현재 점수에는 오늘 학습·과목별 학습 결과만, 모의고사는 모의고사 이력에서만 — 복잡도 완화.
3. 오늘 학습 상자: 위 왼쪽 "오늘 학습 목표", 오른쪽 계획의 "학습시간 · 문항"; 아래 "시스템 추천 학습"과 "과목별 학습".
4. 시스템 추천 학습: 무엇을 할지 먼저 안내 → [학습 시작]. 지난 오답·모름을 **전부** 내면 매일 분량이 불어나 새 문항을 못 푸니 알고리즘으로 적정량만, 맞힌 문항도(찍어서 맞혔을 수 있음) 낮은 빈도로.
5. 과목별 학습: 과목별 학습 이력 + [학습하기](반복 + 새 문항 자동).
6. 과목 이력은 **진도율이 아니라 점수로** — 다른 사용자도 헷갈리지 않게.
7. 오늘 학습 상자 밑에 모의고사를 따로 두고 이력은 따로.

## 원인 (1번)

예상 점수 = ρ(반복 출제 약 10%) × 기출 기억 + (1−ρ) × **처음 보는 문항 정답률**. v0.5.0까지 처음 보는 문항 정답률은 "최근 30문항 그대로"였고,
학습시간은 ρ 부분(기출을 얼마나 기억하나)에만 들어갔다. 시험 사용 팩이 **1회차 100문항뿐**이면 하루 1시간으로도 다 익히므로 시간을 늘려도 오를 곳이 없다.

## 결정

- **학습량 → 처음 보는 문항 정답률(전이)**: 계획 시간으로 더 풀 수 있는 새 기출 비율 g(과목별, 보유 문항 대비)만큼
  `rate' = rate + TRANSFER · g · (1 − rate)`, `TRANSFER = 0.3`. 근거: 인출 연습의 다른 문항 전이 효과는 같은 문항 효과보다 훨씬 작다
  (Pan & Rickard 2018 메타분석, 전이 d ≈ 0.40). 상수는 7단계 실사용 기록으로 다시 맞춘다.
  → 여러 회차 팩이면 시간에 따라 예상 점수가 달라지고, **1회차 팩이면 여전히 거의 그대로**(새 문항이 없음).
- **학습 계획 화면 미리보기**: 저장 전에 "이 계획이면 시험일 예상 점수 n점". 보유 기출이 5회차 미만이면 "학습시간을 늘려도 거의 오르지 않는 이유"를 바로 보여 줌.
- **모의고사는 학습 엔진에서 뺀다**(`loadEngine`이 mode=mock 풀이 제외): 현재 점수·시험일 예상·기억·추천·오늘 푼 수 모두 오늘 학습·과목별 학습만. 모의고사 성적은 모의고사 이력에만.
- **추천 구성 규칙(시스템 추천·과목별 공통)**: 후보를 네 갈래로 — ① 오늘 틀린·모름 ② 지난번 틀린·모름(복습 때 된 것) ③ 맞혔지만 복습 때 된 것(FSRS가 정답은 간격을 길게 → 자연히 드물게, 헷갈림 표시·오래 걸린 정답은 더 자주)
  ④ 새 문항(자주 출제 → 최근 순). **복습(①~③)은 한 묶음의 최대 60%(`REVIEW_SHARE`)**, 나머지는 새 문항, 새 문항이 모자라면 복습으로 채운다.
  밀린 복습은 다음 날로 넘어가며 오래 밀린(잊을 확률 큰) 것부터.
- **홈**: ① 시험일 | D-day ② 현재 점수 | 시험일 예상 점수 ③ 오늘 학습 목표(오른쪽 "1시간 · 40문항", 진행 막대) — [시스템 추천 학습 ›] [과목별 학습 ›] ④ 모의고사(최근 날짜·점수, [모의고사 ›]).
- **시스템 추천 학습 화면**: 갈래별 문항 수와 이유, 과목별 문항 수, 60% 규칙 설명 → [학습 시작 (n문항)].
- **과목별 학습 화면**: 과목마다 현재 ☞ 시험일 예상 점수(막대 + 과락선), 풀이 횟수·마지막 날짜, 오늘 복습·새 문항 수, [학습하기](15문항, 같은 규칙). 진도율은 쓰지 않는다(한 번씩 다 풀면 모두 100%가 되어 실력을 말해 주지 않음).

## 검토한 대안

- 지난 오답을 모두 매일 내기: 분량이 계속 불어나 새 문항을 못 품(사용자 지적) → 상한 60%. 학습 앱의 흔한 기본값(복습 우선 + 새 카드 상한)과 같은 방향.
- 학습시간을 기출 기억(ρ 부분)에만 반영: 1회차 팩에서 변화 없음 — 이번 문제의 원인.
- 모의고사도 점수에 반영: 같은 문항이 학습과 모의고사 양쪽에 섞여 사용자가 점수 출처를 헷갈림 → 분리.

## 영향

- 학습 기록(DB)은 그대로. 모의고사 풀이도 지우지 않고 엔진에서만 뺀다.
- 4단계 게이트 시뮬레이터는 모의고사를 쓰지 않으므로 영향 없음.
- 시험: vitest 78건(실기기 v0.5.0 보완 3건 추가), e2e 4건(추천 화면·과목별 화면·모의고사 분리) 통과.
