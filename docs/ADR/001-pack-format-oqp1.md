# 001. 문제팩 포맷 oqp/1 확정 (1단계)

- 상태: 확정 (2026-10-14, 세션 #2)
- 관련: 개발기준서 4.1, 5.1, 8장 1단계
- 보완: ADR 012(2026-10-18) — 선택 필드 `excluded`·`standard`, flags `subject-reassigned`·`ocr` 추가, 형광 표시 제거 추출기 연결

## 결정

1. **스키마 위치는 `shared/pack-schema.json`** (JSON Schema 2020-12). 개발기준서 8장의 `docs/pack-schema.json` 표기는 9.2 저장소 구조(`shared/`)에 맞춘다.
2. **문항 ID**: `qid = packId-문항번호(3자리)` 예) `SURVEY-2022-1-007`. 과목 정보는 `subjectNo`·`noInSubject` 필드로 따로 둔다. 기준서 4.1 예시(`…-1-07`)보다 단순하고 시험지 번호와 바로 대응한다.
3. **packId = 종목코드-연도-회차**, 시행일은 `exam.date`. 2020년 기사 1·2회 통합 시행은 `round: 1`, `roundLabel: "1·2회 통합"`.
4. **정답 표시 제거 기록 `answerMasking`을 manifest 필수 필드로 둔다.** `leakCheck`가 `passed`가 아니면 두 검증기 모두 `LEAK_CHECK` 오류로 팩을 거부한다. 학습앱 화면에 정답이 비치는 사고를 포맷 수준에서 막기 위함.
5. **정답 출처 기록**: 문항마다 `answerSource`(inline-mark / answer-table / manual)와 `answerCheck`(agree / single / corrected). 보기 표시와 정답표가 둘 다 있으면 교차 검증하고, 불일치는 전처리 단계에서 오류로 멈춘다(사람 검수 후 `corrected`).
6. **`text`에는 정답 표시 원문자(❶~❹)를 일반 원문자로 바꿔 저장**한다. 화면에 표시하지 않더라도 데이터로 정답이 새지 않게 한다.
7. **TS 검증기는 ajv를 쓰지 않고 `app/src/pack/miniSchema.ts`로 같은 스키마 파일을 직접 해석**한다. ajv는 검사 코드를 런타임 생성(`new Function`)해 앱 CSP `script-src 'self'`에 막힌다. 스키마에 새 키워드를 쓰면 miniSchema가 즉시 예외를 던지므로 조용히 누락되지 않는다.
8. **두 검증기의 일치는 `shared/fixtures/cases.json`으로 보장**한다. 정상 더미 팩(`valid-pack/`)에 변경을 가한 22개 사례에서 두 검증기가 같은 오류 코드 집합을 내야 한다(pytest·vitest 공통).

## 정답 표시 제거 방식

| 원본 표시 | 제거 방법 | 상태 |
|---|---|---|
| 검은 음영 번호(❶~❹, 텍스트층 있음) | 텍스트층 좌표로 위치를 찾아 흰색으로 지우고, 같은 페이지의 같은 번호 일반 원문자(①~④) 픽셀을 옮겨 붙임 | 구현·검증 완료 |
| 형광펜 표시(노란 상자, 벡터) | **PDF 객체 단계에서 노란 채움 사각형만 지우고 렌더링**(pypdfium2 `remove_obj`). 그림 속 파란 화살표 등 다른 색은 유지 | 실물 확인 완료(2026-10-14) → **추출기 연결 완료(2026-10-18, ADR 012)**: 토목 2024-3 120문항 팩 |
| 형광펜 표시(스캔·래스터) | 보기 번호 상자 안의 채도 높은 픽셀만 흰색으로 `remove_highlight()`. 페이지 전체에 적용하면 컬러 그림이 손상되므로 반드시 번호 주변으로 한정 | 함수·단위시험만 |
| 표시 없음 + 마지막 페이지 정답표 | 마스킹 없이 정답표만 읽음(`none-needed`) | 정답표 파서 구현 완료 |

- 지문 속 원문자(예: "❶~❹의 각을 관측")는 정답 표시가 아니다. 앞 글자와의 간격(6pt 미만)으로 보기 번호와 구분하고, 그대로 둔다(`stem-has-circled-glyph` 표시).
- 마스킹 후 보기 번호 자리의 잉크 비율을 다시 재서 채운 원문자 흔적이 남았는지 검사한다(일반 원문자 최대 0.20, 채운 원문자 최소 0.60, 기준 0.42).

## 검토했으나 보류

- PDF 콘텐츠 스트림에서 글리프 자체를 바꾸기(pikepdf): 글꼴 부분집합에 일반 원문자가 없을 수 있어 범용성이 낮음
- ajv 표준 컴파일 코드를 빌드 시 생성: 가능하나 빌드 단계·의존성이 늘어 1단계 범위를 넘음

## 추가 확인 (2026-10-14) — 두 번째 정답 표시 유형

토목기사 2024년 3회 경향문제 PDF(한솔아카데미, 18쪽, 6과목 × 20문항)로 확인했다.

- 정답 표시: 보기 번호 뒤의 **노란 채움 사각형(RGB 1,1,0) 벡터 객체**. 보기 번호 자체는 일반 원문자(①~④) 텍스트
- 정답표: 없음 → 표시가 유일한 정답 출처(`answerSource: inline-mark`, `answerCheck: single`)
- 수식이 사용자 정의 글꼴(PUA 문자)로 들어 있어 `text` 추출 품질이 낮음 → 키워드·유사도(6단계)에서 보완 필요
- **포맷 변경 없음**: `answerMasking.method`의 `highlight-remove`, 문항 `answerCheck: single`로 그대로 표현된다
