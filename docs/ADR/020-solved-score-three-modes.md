# 020. 현재 점수 = 푼 문항 정답률, 학습 방식 셋으로 단순화("오늘 학습 마치기"·"이어서 학습" 삭제), 과목 막대 안내창 — 앱 v0.11.0

- 상태: 확정(구현) 2026-10-21, 세션 #10 — 단원 선택(4번)은 **보류**(아래 4절, 사용자 결정 대기)
- 계기: 사용자 실사용 보완 요구 5건(2026-10-21)

## 1. 현재 점수 = 실제로 푼 문항 중 정답 비율 (요구 1·3)

배경: v0.10.8까지 현재 점수는 "보유 문항 전체 중 최근 답이 정답인 비율"(안 푼 문항 0점). 팩을 많이 넣을수록(5~10년치) 점수가 거의 0에 머물러 학습 성과가 보이지 않았다.

결정(`engine/exam.ts` `solvedScores`):
- 분모 = **한 번이라도 푼 문항**. 같은 문항(다른 회차의 같은 내용 = 학습 단위)은 여러 번 풀어도 1문항 — **회독 수는 반영하지 않음**
- 정답/오답 = 그 문항의 **가장 최근 답**. 모름은 오답, [쉬움]은 정답(모름으로 바꾸면 오답)
- 과목별(과목별 학습 화면)과 전체(홈 "현재 점수", 현행 과목만) 같은 규칙. 푼 문항이 없으면 "—"
- 모의고사 풀이는 그대로 빠짐(모의고사 이력에만 — ADR 011)
- 홈 점수 아래 "푼 n문항 중 정답 m", 과목 카드 아래 "푼 n문항 · 정답 m · 마지막 날짜"(예전 "풀이 n회"는 회독이 섞여 뺌)
- 시험일 예상 점수(ADR 013)는 바꾸지 않음 — 예상은 여전히 "보유 기출 전체 + 처음 보는 문항" 기준이라 두 숫자의 뜻이 다름(현재 = 지금까지 푼 것의 정답률, 예상 = 실제 시험을 보면)

검토한 대안: 출제 횟수 가중(같은 문항이 3회 출제면 3으로) — 사용자가 손으로 세어 맞춰 볼 수 없어 뺌.

## 2. 과목별 학습 — 안내문 대신 막대 안내창 (요구 2)

- 화면 위 안내문 두 문단(막대 읽는 법·학습하기 묶음 크기)을 지우고 한 줄("막대를 누르면 / 막대에 마우스를 올리면 점수 설명")만 남김
- 막대 영역(`bar-hit`): **PC(마우스)는 올리면 열리고 벗어나면 닫힘, 손가락·펜은 누르면 열고 다시 누르거나 바깥을 누르면 닫힘**, 키보드 Enter/Space·Esc. 한 번에 하나만
- 안내창 내용은 **그 과목의 숫자로**: 현재 점수(푼 n중 정답 m, 셈법), 시험일 예상, 과락선·색 기준, 오늘 학습할 문항(복습·새 문항)과 [학습하기] 묶음 크기
- 기기 판정은 문구에만 씀(`(hover: hover) and (pointer: fine)`) — 동작은 pointerType으로 나눠 터치 노트북·펜 태블릿도 함께 됨

## 3. 학습 방식 셋 — "오늘 학습 마치기"·"이어서 학습"·"나중에 이어서 하기" 삭제 (요구 5)

배경(사용자 사례): 어제 [오늘 학습 마치기] → 다시 [시스템 추천] → [나중에 이어서 하기]로 나감 → 오늘 아침 홈 단추가 "이어서 학습 (52문항 남음)", 목표는 "1시간 120문항", 막대 밑은 "오늘 8 / 120". 원인:
- "이어서 학습"은 **날짜와 관계없이** 열린 묶음을 찾고, 남은 수를 **그 묶음 기준**(어제 만든 60문항 − 8)으로 셈 → 오늘 기준(8/120)과 어긋남
- 묶음(세션)은 "지금 풀 차례"일 뿐인데, 마치기·이어서·나중에가 그 묶음의 상태를 사용자에게 관리시켰음. 답은 하나하나 바로 원장에 저장되므로 "마치기"가 저장·채점에 하는 일은 없었다(묶음을 닫고 요약을 보여 줄 뿐)

결정:
- 학습 방식은 **① 시스템 추천 학습(앱이 과목·복습·새 문항을 섞어 냄) ② 과목별 학습(과목을 골라, 그 과목 안에서 같은 규칙) ③ 모의고사** 셋뿐
- ✕(풀이 중 나가기): 시스템 추천·과목별·다시 풀기는 **묻지 않고 홈으로**, 묶음은 닫음. 다음에 시작하면 **오늘 남은 목표만큼 오늘 기록으로 다시 고름**(오늘 틀린 문항이 맨 앞) → 하루가 바뀌면 어제 묶음이 이어지지 않음
- 새 묶음을 시작할 때 열린 묶음은 모두 닫음(`closeOpenToday` — 앱 강제 종료 등으로 남은 것까지)
- 홈 단추는 늘 **[시스템 추천 학습]**, 아래 줄에 "오늘 남은 n문항"(목표를 채웠으면 "오늘 목표 완료 · 추가 학습") — 막대 "오늘 x / 목표"와 같은 숫자
- "오늘 학습 마치기" 요약 화면 → **[오늘 기록 보기]**(오늘 푼 문항이 있을 때 홈 링크, 보기만 함). 목표 달성 창·결과 화면의 [오늘 학습 마치기] → [홈으로]
- 모의고사는 실제 시험처럼 ✕ → 멈추고 나중에 이어서 풀기 / 지금 제출(ADR 014 12절) 그대로
- 하루 경계는 지금처럼 기기 시각 자정(`startOfDay`)

참고한 사례: Anki는 "마치기" 단추 없이 하루 한도가 날짜 경계(기본 새벽 4시)에 다시 채워지고, 사용자는 대기열이 빌 때까지 풀기만 한다 — 이 앱도 같은 구조가 됨. 새벽 공부를 고려한 날짜 경계 조정(예: 새벽 4시)은 BACKLOG.

검토한 대안:
- A. "이어서 학습"을 남기되 오늘 만든 묶음만, 남은 수는 오늘 목표 기준 — 단추 이름이 상황마다 바뀌는 문제(시스템 추천 ↔ 이어서)는 그대로라 뺌
- B. ✕에서 "정말 나갈까요?" 확인 — 답이 이미 저장돼 잃는 것이 없어 뺌(실수로 눌러도 다시 시작하면 같은 규칙으로 고름)

## 4. 단원 선택(요구 4) — 검토, 보류 제안

필요한 것:
1. 종목·과목별 **단원 목록**: 큐넷 출제기준의 주요항목(대개 과목당 3~8개)·세부항목. 공식 OpenAPI(ADR 019 이후 확인)는 과목까지만이고 항목은 출제기준 PDF에만 있음 → 전처리기 3단계(출제기준 PDF 읽기)가 먼저
2. **문항마다 단원 붙이기**(가장 어려움): 기출 PDF에는 단원 표시가 없음. 선택지
   - (가) 세부항목 낱말 사전 + 글자 2-gram/TF-IDF 유사도로 자동 배정 → 검수 창에서 확신 낮은 문항만 사람이 고침. 측량 2011 재배정(과목 단위)이 이 방식이었고, 단원은 과목보다 훨씬 잘게 나뉘어 낱말이 겹침(예: 측량학 "거리측량"·"수준측량"이 같은 공식을 씀) — 정확도는 실측 전까지 모름
   - (나) PC에서 내려받는 작은 다국어 임베딩 모델(인터넷·서버 없이) — 정확도는 낫지만 실행파일이 수백 MB 커짐
   - (다) 사람이 전부 분류 — 종목당 수천 문항이라 동료 배포 방식에 맞지 않음
   - (라) 외부 AI(API)로 분류 — "서버·외부 API 없이" 원칙과 충돌, 동료 PC 설치 부담
3. 팩 포맷: 문항에 선택 칸 `unit`(없으면 단원 없음)만 더하면 oqp/1과 호환. 앱은 팩에 단원이 있을 때만 과목 → 단원 화면을 보여 주면 됨(앱 쪽은 비교적 단순 — 엔진의 과목 세션에 단원 필터 하나)

판단: 앱 쪽은 버그 위험이 크지 않지만, **잘못 붙은 단원은 사용자에게 바로 보이는 오류**이고 그 정확도는 전처리기에 달려 있음. 전처리기 워크플로우 근본 재검토(`docs/REVIEW-v0.4-AGENDA.md`)·3단계와 함께 결정하는 것을 제안 — 그때 측량 1개 과목으로 (가) 방식 정확도를 먼저 재 보고(목표 예: 자동 배정 90% 이상 + 확신 낮은 문항 검수), 넘으면 `unit` 칸·앱 단원 화면을 만든다. 안건 문서에 추가함.

## 5. v0.11.1 — 오늘 학습 기록 화면(실기기 Q1 의견, 2026-10-21)

- 문제: 오늘 정답률 13%인데 아래에 "현재 55.2점 → 계획 이행 시 75.9점"(전체 기록 기준)이 함께 있어 헷갈림. 오늘 안 푼 과목은 빠짐. 여백에 비해 글자가 작음(50대 이상 사용자)
- 결정: 이 화면은 **오늘 것만** — ① 오늘 목표: 푼 수 / 목표 문항(큰 숫자)·막대·"남은 n문항 — 홈의 [시스템 추천 학습]으로 이어 갑니다"(다 했으면 초록 "오늘 목표를 다 풀었습니다")·공부 시간 / 계획 ② 오늘 성적: 정답 ÷ 푼 문항(큰 숫자) + 푼 문항·정답·오답·모름 네 칸 ③ 과목별 오늘: **현행 과목 전부**, 안 푼 과목은 "0 / 0"(흐리게), 정답률 %. 현재 점수·시험일 예상은 빼고 "홈에서 봅니다" 한 줄
- 글자: 큰 숫자 48px, 칸 숫자 30px, 과목 줄 19~22px, 설명 16px 이상

## 6. v0.11.2 — 이름·화면 다듬기(실기기 의견, 2026-10-22)

- 홈 "현재 점수" → **"누적 점수"**: "현재"는 오늘을 떠올리게 함. 실제로는 지금까지 푼 기록 전체 기준(과목별 안내창도 "막대 = 누적 점수")
- 오늘 학습 기록: "오늘 목표" → **"오늘 학습량"** — 한 줄에 "푼 수 / 목표 문항"과 "공부 시간 / 계획 시간"(같은 모양, 아래 공부 시간 줄 삭제), 남은 수는 두 줄("n문항이 남아 있습니다" / "[시스템 추천 학습] 또는 [과목별 학습]으로 이어 가세요"). "과목별 오늘" → **"과목별 실적"** — "푼 문항 / 과목별 오늘 목표 문항 · 점수(정답 ÷ 푼 문항)", 아래 안내문 삭제. 카드 제목 20px 진하게, 줄 간격을 줄여 휴대폰 한 화면(390×844)에 들어감
  - 과목별 오늘 목표 = 오늘 푼 수 + 지금 시작하면 남은 목표에서 그 과목에 배정될 수(시스템 추천 구성 규칙). 미리 고정된 과목별 목표가 없어서 이렇게 셈 — 합계는 오늘 목표와 같음, 목표를 다 채웠으면 푼 수 그대로
- 풀이 화면 위: "회차 · n번 · 과목명" → **"과목명 회차"** — 과목명은 파랑·진하게(15.5px), 회차는 옅게(13px), 한 줄 그대로라 풀이 영역 높이 변화 없음. 문항 번호는 뺌

## 7. v0.11.3 — 시스템 추천 학습 화면(실기기 의견, 2026-10-22)

- 제목 "오늘 추천 n문항" + "오늘 목표 1시간·40문항 중 남은 분량" 두 줄 → 한 줄 **"오늘 목표 40문항"**, 푼 게 있으면 **"오늘 목표 40문항 중 n문항 남음"**, 목표를 채운 뒤에는 **"추가 학습 15문항"**
- 문항 수 계산 카드: 늘 보이던 상자 → **제목에 마우스를 올리면(PC) / 제목을 누르면(폰·태블릿·펜)** 뜨는 안내창(과목별 학습 막대 안내창과 같은 방식, ⓘ 표시). 내용: 목표 문항 수는 "홈 > 학습계획 설정"의 하루 학습시간에 따라 자동 계산 / 오늘 계획 n / 문항당 n = n문항 / 문항당 시간은 풀이 20건 이상부터 통계로 자동 재설정(지금 기준). 추가 학습이면 맨 위에 "목표를 다 풀어 15문항씩 추가"
- 과목표: 복습·새 문항 오른쪽에 **목표(추가 학습이면 "추가")** 열 = 과목별 합, 맨 아래 **합계** 줄

## 8. v0.11.4 — 풀이 화면 머리·추천 과목표·과목별 학습 전면 개편(실기기 의견, 2026-10-22)

- 풀이 화면 위: **[성적] 단추 삭제**(시스템 추천·과목별). 가운데 진행 수, 오른쪽에 **과목명(파랑·진하게) / 회차** 두 줄. 모의고사 [제출]은 남은 시간 줄 오른쪽으로 옮김(제출은 꼭 필요)
- 추천 과목표: 마지막 열 이름은 늘 **"목표"**, 숫자 열 좁게·오른쪽 정렬(과목 열 넓게), 목표 열 굵게
- **과목별 학습 화면**: 막대·과락선·누적/예상 점수·푼 문항 수·안내창을 모두 빼고 ① 오늘 목표 제목(시스템 추천과 같은 글·같은 문항 수 계산 안내창 — `GoalTitle`) ② "학습할 과목을 선택하세요" ③ 과목 | [학습하기 (n문항)]. 점수는 홈(누적·예상)에서
- **오늘 목표 연동(검토 결과)**: 오늘 푼 수는 v0.7.2부터 시스템 추천·과목별·다시 풀기를 모두 합쳐 셈 → 시스템 추천에서 2문항 풀면 과목별도 "오늘 목표 40문항 중 38문항 남음". 과목 단추 n = min(남은 문항, 그 과목에 지금 낼 문항) — 그 과목 문항이 모자라면 더 적게 보임
- 추가 학습 단계도 남은 수를 셈: `stageLeft` — 목표 뒤에는 15문항 단위로 "추가 학습 15문항 중 n문항 남음"(묶음 크기도 n). 시스템 추천·과목별·묶음 크기가 한 함수를 씀
