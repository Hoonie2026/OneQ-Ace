# 4단계 게이트 — 학습 엔진 시뮬레이션 결과

- 실행: `cd app && npm run gate` (약 35초, 결정적 — 같은 코드면 같은 결과)
- 기준: 개발기준서 6.6 "가상 학습자 3종 × 시험일 60·30·14일에서 과락 과목이 해소되는지"
- 기록: 2026-10-15 세션 #4. 엔진은 `app/src/engine/`에만 있고 화면에는 아직 연결하지 않음(앱 0.1.3 그대로, 5단계에서 연결)

## 판정: **미통과** — 27회 중 23회 통과

| 조건 | 결과 |
|---|---|
| 1. 시험일 진짜 점수에 과락(40점 미만) 없음 — **기준서 게이트** | 24/27. **과락형·14일 3회 모두 미달(35·37·39점)** |
| 2. 평균이 비교 기준(회차 순서대로 풀이)보다 높거나 같음 | 27/27 |
| 3. 시험 전날 예상 평균이 진짜 평균과 ±5점 안 | 26/27 (균형형·14일 시드1: 5.1점 차) |
| 4. 평균 60 미달이면 첫날 시간 부족 경고 | 27/27 |

60·30일 시나리오는 모두 통과했다. 실패는 **14일 안에 20%짜리 과목을 40점으로 올려야 하는** 가장 어려운 경우에 몰려 있다.
같은 시간에 "약한 과목만 푸는" 참고 상한은 44~45점까지 가므로 **불가능한 목표가 아니라 엔진의 배분 문제**다.

## 원인 분석(14일·과락형)

- 실력을 알기 전 진단 문항(과목당 15개)과 그 복습이 강한 과목에도 시간을 쓴다.
- 14일 동안 과목당 첫 풀이가 30~60건뿐이라 과목 실력 추정이 ±10%p 흔들린다. 실제 55%인 과목이 30%대로 잡히면
  과락 위험(40 + 안전여유 10 미만)으로 분류돼 노력이 분산된다.
- 이 경우 학습자는 어차피 평균 60을 못 넘기므로(첫날 부족 경고가 뜸) 합격 여부는 바뀌지 않지만, 게이트 조건은 충족하지 못한다.

## 다음 세션 선택지(사용자 결정)

1. **엔진 보완 후 재시험**: 과목 실력 추정에 복습 결과도 쓰기(문항 반응 모형), 과락 깊이에 비례한 과목 가중, 진단량을 남은 기간에 맞추기
2. **경고로 전환**: 시험까지 남은 시간으로 과락 해소가 어렵다고 예측되면 "○과목 집중 모드 / 하루 ○분 추가"를 띄우고, 게이트를 "해소 또는 사전 경고"로 조정
3. 14일 시나리오의 하루 학습시간을 현실값(예: 90분)으로 다시 정의 — 근거가 있을 때만
