| 설치한 학습앱(standalone) | 모든 기기 | 팩 없으면 문제팩 가져오기 | 접힘: 전처리기 |

| 학습앱 설정 | 모든 기기 | 학습앱 링크·전처리기 링크 복사·보내기 | 설치 방법·전처리기(접힘) |

재설계 때 다시 볼 것(사용자 확인 사항 포함):
- 입구를 둘(링크 2개)로 둘지, 하나로 두고 화면에서 고르게 할지 — 받는 사람이 링크 종류를 구분하는 부담
- 공유의 단위: 학습앱 링크 + 문제팩 파일을 따로 보내는 지금 방식 vs 다른 방식(예: 받은 사람이 팩을 어디서 받는지)
- 브라우저 화면(설치 전)에서 가져오기를 접어 둔 것이 맞는지 — 아이폰은 Safari와 홈 화면 앱 기록이 따로, 안드로이드·PC는 같음
- PC 학습앱 = 브라우저 정식 설치(세션 #18)의 실제 모습 — 🖥P26 결과가 근거가 됨(재설계 전에 해 두면 좋음)
- 아이폰 안내: iOS 16.4+는 Chrome·Edge에서도 「홈 화면에 추가」 가능 — 지금 앱은 "Safari로 옮기세요"(사용자에게 제안만 함, 미결)
- 전처리기 설치 프로그램과 학습앱의 관계(따로 설치 유지 — 사용자 11-11 "자동으로 둘 다 깔면 혼란")
- 원칙(사용자): 설치 단계 안내에 문제팩 가져오기를 넣지 않음, 휴대폰 브라우저를 단정하지 않음, 서로 상대 안내는 서브

## 교훈(계속 유효한 것만)

- "없다"는 결론은 한 번 더 찾아본다(큐넷 API 사례)
- "같은 숫자"(오늘 목표·남은 수 등)는 한 함수에서 — 화면마다 따로 세면 어긋남
- PC와 클라우드 양쪽에 같은 파일을 쓰지 않는다 → GitHub 한쪽으로만, PC는 pull
- 작업 스레드에서 창 띄우기 금지(람다 연결 → 프로그램 죽음)
- 시험용 Chromium은 실기기 Chrome보다 오래됨 → 실기기 전에 PC Chrome으로 배포본 확인
- OCR은 엔진마다 실패 모양이 다름(빈 글·글자 누락) → 실제 엔진으로 PC 실측을 반복하고, 결과 파일에 판단 근거(줄별 기록)를 남겨 원격으로 원인을 짚는다(세션 #16)
