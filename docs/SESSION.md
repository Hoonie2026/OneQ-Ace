### 첫 30분 — 상태 확인
1. PC에서 `cd preprocessor` → `pip install -r requirements.txt` → `python -m pytest -q tests`(35건, `source_pdf/`가 있으면 실제 PDF 통합 시험 포함)
2. 클라우드 작업 공간에는 `source_pdf/`·`packs/`가 없다(커밋 금지 파일) → 필요한 PDF만 그때그때 올림. 건설안전기사 PDF(`source_pdf/safety_기출_2003_2022`, 60개)는 아직 한 번도 처리하지 않았다
3. 2011 3회차 재배정 검수(사용자): `python -m oneq_prep (측량 2011 PDF 3개) ..\packs --cert SURVEY --prepared-by 이름` → `packs/review/report.html` → 재배정 제안 확인 → **검수 완료** → 같은 명령 재실행 → 2011 팩 3개

### 무엇부터 할지 — 사용자가 고를 선택지(우선순위는 정하지 않음)
| 갈래 | 내용 | 열린 질문 |
|---|---|---|
| A. 종목 넓히기 | 건설안전기사(60회차) 프로필 만들고 처리, 철도토목기사 프로필 확정, 토목 과목명 큐넷 대조 | 출품 시연 종목을 몇 개로 할지. 건설안전 PDF가 측량과 같은 comcbt 교사용 형식인지 먼저 확인 |
| B. 스캔본 OCR | 실제 스캔 PDF(③)로 경계·보기 번호 보정 | Tesseract 유지 vs 다른 엔진(PaddleOCR 한국어 PP-OCRv5 등) 비교 — 실제 스캔본 확보가 먼저 |
| C. 창 프로그램·exe | HTML 검수 흐름을 창으로 감싸기 | 기준서 D8(PySide6 + PyInstaller) 그대로 vs `pyside6-deploy`(Nuitka) vs 지금의 HTML 보고서 + 로컬 실행만 유지 — 사내 PC 배포 조건(보안 프로그램, 설치 권한)에 따라 |
| D. 6단계 유사 문항 군집 | 같은·변형 문항 군집을 전처리에서 만들어 팩에 넣기 | 지금 앱은 글자 2-gram으로 직접 계산(`engine/similar.ts`). 옮기면 oqp/2(포맷 변경) — 이득이 있는지 |
| E. 팩 포맷 oqp/2 | contentHash에서 문항 번호 빼기, 원본 과목 번호(noInSubject) 표시 | 이미 배포된 팩·앱 기록과의 호환(ADR 002 재연결) |
