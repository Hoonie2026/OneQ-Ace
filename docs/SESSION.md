## 작업 방식

- 클라우드에서 고치고 시험한 뒤 GitHub `main`에 바로 푸시(학습앱은 Pages 자동 배포). PC 저장소 파일은 직접 고치지 않음 — PC는 작업 전 `git fetch` → `git reset --hard origin/main`
- PC 일은 `docs/PC-TODO.md`에만 적고, 사용자가 실행 후 "Pn 끝"으로 알림
- 릴리스 게시·수정은 사용자가 GitHub 웹에서(Claude 세션은 릴리스 권한 없음)
- 클라우드는 큐넷에 접속할 수 없음 → 실제 접속 확인은 PC
- 저장소는 공개 — 소속·업무·개인 일정, 실제 기출 글, PC 사용자 폴더 경로는 커밋하지 않음

## 교훈(계속 유효한 것만)

- "없다"는 결론은 한 번 더 찾아본다
- 같은 숫자는 한 함수에서 — 화면마다 따로 세면 어긋남
- 기능을 없앨 때는 학습앱·생성기·팩 형식·문서를 함께 훑어 흔적까지 정리
- OCR은 엔진마다 실패 모양이 다름 → 실제 엔진(PC Windows OCR) 결과를 기록 파일로 받아 원격에서 재현
- 글자 완전 일치에 기대는 규칙(같은 문항, contentHash)은 OCR 문제팩에서 깨진다 — 한글 정규화 + 사람 판정 표본으로 기준을 정할 것(ADR 030·031)
- 기출은 해마다 보기 순서가 바뀐다 — 정답 '번호'를 다른 회차로 옮기려면 보기 순서까지 같은지 먼저 확인
- 기기에 저장해 두는 계산 결과(예: 출제 구성)는 계산 방식이 바뀌면 판 번호로 다시 계산하게 할 것
- 규칙을 바꾼 뒤 비교는 문항 머리만이 아니라 **과목 배정·제외 사유까지** 본다
- 숫자를 사용자에게 보여 주기 전에 "사용자가 납득할 수 있는가"를 먼저 본다
